# プロジェクト概要・蔵書を扱う不変条件・固有ルール

## プロジェクト概要

- プロジェクト名: SpineBox — ローカルの自炊本(漫画中心・小説も)を管理し、ブラウザで読む Web アプリ。日本語のみ想定
- ゴール: `GOAL.md`(目的・作らないもの・段階計画と完了条件)。Issue を起こすときは、どの段階のどの完了条件に向かう作業かを書く
- 技術スタック: Python 3.12 / FastAPI / SQLite(FTS5 trigram)/ React + Vite / アーカイブは Python 標準 zipfile + 7-Zip CLI(`7z.exe`)
- 本番環境: サーバー機 `DESKTOP-80AKMUB`(Windows)で常駐する単一ユーザー・単一プロセス。
  開発機(`DESKTOP-R9O3S3K`)とは別マシンで、蔵書もサーバー機側にある。ほかの端末(スマホ等)から LAN 越しにブラウザで使う。
  CD は未導入(アプリが動く段階で検討する)
- フロント変更後の検証方法: 実装後に必ずブラウザで動作確認する(モバイル幅 375px 相当を含む)

## 蔵書を扱う不変条件

利用者が長年ためた蔵書を預かるアプリなので、壊したら取り返しがつかない。理由と経緯は `wiki/`。

- **蔵書の元ファイル・元フォルダに書き込まない。** スキャン・閲覧・メタデータ取得は読み取りのみ。
  例外はユーザーが明示実行する整理処理だけで、それも「プレビュー → 実行 → 元に戻す」ができ、
  同一ドライブの作業場で作って検証してから改名で確定し、元は退避フォルダへ移すだけで**削除しない**。
  唯一の例外は、利用者が整理の画面で「CBZ 化した元を削除する」を選び、元に戻せないことを確認して実行したときで、
  そのときも全巻の確定・検証と DB の記録が済んでから、その操作の退避フォルダの中だけを消す(#153)。
- **アーカイブ内のエントリ名を、検証せずにディスク上のパスへ使わない**(`..`・絶対パス・ドライブ文字)。
  展開キャッシュは元の階層を再現せずハッシュ名で置く。キャッシュは消えてもよいものとして扱う。
- **展開には上限を設ける**(展開サイズ・エントリ数・入れ子の深さ)。超えたものは理由を記録してスキップする。
- **ファイル名・フォルダ名は「候補」。** 巻番号・話数や作品の確定は中身と確認済みのソースで行う
  (実データで、名前の巻範囲と中身が食い違う例がある)。
- **作品の表示タイトルと、名寄せのキーにするタイトルは、利用できる限り日本語を正とする**
  (公開 DB・手動編集・コンテナ名由来の日本語)。ファイル名由来のローマ字は候補・別名として残し、日本語が得られたら置き換える。
  実装は `spinebox/works.py choose_survivor()` / `spinebox/linking.py _prefer_japanese_value()`(#212)。
- **ユーザーが手で編集したメタデータ項目を、外部ソースの取得結果で上書きしない。** 外部ソースは空欄だけを埋める。
- **指定された蔵書フォルダが一時的に存在しない・読めないとき(外付けドライブ未接続など)、DB の蔵書レコード・手動編集メタデータ・読書履歴を削除しない。**
  オフラインとして扱い、再接続時にそのまま復元できるようにする。
- **蔵書・サンプル(`_参考/`)・DB・展開キャッシュをコミットしない。**
- **蔵書のパスはサーバー機のパスとして扱い、開発機の環境(ドライブ文字・ユーザー名)を前提にしない。**
  ドライブ文字やルートフォルダは設定で持つ。開発機での動作確認は `_参考/` のサンプルで行う。
- **インターネットへ直接公開する前提で作らない。** LAN 内からの利用を想定し、待ち受けアドレスは設定で絞れるようにする。

## GitHub Issue 連携

リポジトリ: `kant0123/SpineBox`(private。`gh` CLI 認証済み)。Projects ボードは使わない。

- **main へマージする変更は、規模にかかわらず着手時に Issue を確保する**(重複起票しない。コミットが発生しない調査・回答は対象外)。仕様・受け入れ基準は Issue 本文に書く。手順は `worktree-start`。
- **完了時は `gh issue close <番号> --comment "<要約>"` で、実装内容の要約を必ず Issue に残す。** そのため PR 本文・コミットで `Fixes #` / `Closes #` を使わない。素の `#<番号>` 参照に留める。手順は `pr-finish`。
- **Issue に秘匿情報(Webhook URL・トークン・鍵)を書かない。** private リポジトリでも同じ。
- **スコープ外の問題を発見したときは、発見した時点でその場で起票する。** 手順は `file-issue`。

## プロジェクト固有ルール

- テストコマンド: `python scripts/ci_local.py --no-report`(CI と同じ検査。`review/tests`・`tests/`・hook のテスト・wiki-lint)
- 命名規約: Python は snake_case、DB のテーブル・カラムも snake_case
- コミットメッセージの言語: 日本語(`feat:` などのプレフィックスは英語のまま)
- 外部メタデータ取得のエラー方針: ベストエフォート。失敗・タイムアウトでスキャンや閲覧を止めない。
  各ソースのレート制限を守り、生の応答は保存して再取得を減らす
- 秘匿情報の扱い: 外部 API のキー(楽天ウェブサービスなど)はリポジトリ外の設定ファイルに置き、
  ログ出力・コミット・Issue 記載をしない
- agy レビューの分野は `spinebox`(`review/domain_invariants.json`。`review/agy_review.py` の既定値)
