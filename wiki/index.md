## Components — モジュール・機能単位 (`components/`)

- [[archive-reading]] — アーカイブの目次読みと 1 エントリの読み出し。拡張子ではなく先頭のマジックバイトでの形式判定、zip の名前の復号順(UTF-8 フラグ → 0x7075 → cp932)、7-Zip CLI での 7z / rar の読み方と異常系、危険なエントリ名と展開上限
- [[backend]] — FastAPI のバックエンド(設定・DB・スキャン・閲覧 API)。フロントと共有する API 契約と、蔵書レコードを消さない offline / missing の扱い
- [[bookmarks]] — ブックマーク(#86)。作品・巻に付ける印と一覧(付けた順・作品名順)。整理で巻が置き換わると印を移し(写さない)元に戻すと戻す、作品の統合では吸収先へ移す、オフライン・分解済みの親の印も一覧から落とさない理由
- [[frontend]] — 蔵書一覧とリーダーのブラウザ側(frontend/)。Peach と同じ画面構成(常に表示するサイドバー・管理のタブ)、作品カード → タイトル一覧 → 作品の管理ページの導線、読書位置のページ番号の規則、巻情報の読み込み待ち・取得失敗の表示、ライト/ダーク、モック API、CI への組み込み
- [[inbox]] — 受け入れ(フェーズ 4)。受け入れフォルダを蔵書と同じスキャナーで検出(同期)→ 作品・番号・重複・対象外の理由つきで整理案をプレビュー → 利用者が選んだものだけ承認で書庫へ入れる(元は受け入れフォルダの退避へ移すだけ・履歴から元に戻せる)。確信度が低い名寄せ・読めない番号・重複は自動で決めない
- [[manga-reader]] — 漫画(画像)の巻のリーダー(#136)。表示・ページ送り・見開き・ズーム・しおりは外部ライブラリ manga-viewer(MIT)に任せ、読書位置のサーバー保存と「続きから読む」の結線、しおりのサーバー保存(整理・巻への分解での引き継ぎ)、巻のブックマーク・次巻のボタンを足す。GitHub のコミットに固定した理由、見開きの切替を廃止した経緯、却下した代替案
- [[metadata-clients]] — 公開 DB クライアント(spinebox/metadata/)の入口。検索の入出力の型、失敗の表現、生応答の保存(metadata_responses)、取得元ごとのレート制限、確からしさの出し方、結線が使う入口。結線そのものは [[metadata-linking]]
- [[novel-reader]] — 小説(EPUB・テキスト)の巻と縦書きリーダー。EPUB の HTML を信用しない 3 段の安全方針(サーバーの許可リスト・ブラウザの作り直し・CSP)、文字コード判定と分割、行の途中で切らないページ割り、区切り+割合の読書位置、却下した代替案
- [[organize]] — 整理処理(1 ソース → 巻ごとの CBZ、命名テンプレートどおりの作品単位の改名・移動、範囲指定のファイル名の整理とテンプレートでの振り分け。範囲指定では CBZ 化もまとめて行える。名前の競合は既定でファイル数の多い方を残し、プレビュー結果の行を選んで残す方を変えられる。CBZ 化する元は負けた巻だけを外して残りを CBZ にし、画像だけの EPUB も CBZ にできる)。蔵書に書き込む唯一の経路。作業場で作って全巻検証 → 改名で確定 → 元を退避(利用者が選んだときだけ削除) → 空になった元フォルダの削除、のジャーナルつき往復と元に戻す。テンプレートの規則、安全設計の理由と却下した案

## Concepts — 横断的な仕組み・設計判断 (`concepts/`)

- [[cover-thumbnails]] — 作品カードの表紙(#75)。最小の巻番号の巻の 1 ページ目を縮小してハッシュ名で置く。一覧からは取り出し・7-Zip が要らない巻だけその場で作り、入れ子の巻は開いた後か明示操作(管理のデータ管理タブの「表紙のみ補完」)で作る理由と、却下した代替案
- [[data-jobs]] — データ管理とジョブ(#83)。スキャン・補完・表紙・解析・重複・名寄せ・受け入れの同期を 1 本ずつ動かす待ち行列と履歴(jobs 表)。依頼は待ち行列、その場で結果を返す API は他が動いていれば 409、中止は区切りで止める。1 本ずつにした理由と却下した代替案
- [[duplicate-detection]] — 別スキャンの重複候補の検出。全ページの dHash の集合と巻番号の候補で判定し、自動では消さない。しきい値の根拠(実データの距離の分布)、全ページを指紋にした理由、却下の持ち方、計算の範囲
- [[extraction-cache]] — 内側アーカイブだけを開いたときにハッシュ名で取り出す展開キャッシュ(ディスク)と、7z / rar のページと目次を置く RAM 層。どちらも容量上限つき LRU、スキャンでは使わない。RAM 層を 7z / rar に絞った計測結果と、実データでの計測
- [[follow]] — フォロー(#87)。Peach のフォローを「フォローした作品の続刊・欠けを公開 DB で調べて知らせる」に読み替えた理由(本の入手はしない)、国立国会図書館サーチの連携した組だけで数える取得の方針、確認済みの持ち方、組み込み口(#85 のサイドバー・管理のタブ、#83 のジョブ)
- [[metadata-linking]] — 公開 DB の情報を作品・巻へ結線する規則(#50)。連携(work_links)の自動/確認待ちの基準、空欄だけを埋める・手動は不変・名前由来の値を置き換える条件、英語の語彙を日本語にして反映する規則(#74)、あらすじの廃止(#82)、失敗の扱い、保存場所(全文検索・絞り込みが乗る列)、却下した代替案
- [[metadata-sources]] — 公開 DB 3 つ(国立国会図書館サーチ・AniList・MangaUpdates)の癖・制限・利用条件・採否の理由と、実通信で確かめた応答の違い、既定のレート制限の根拠
- [[recurring-review-findings]] — レビューで妥当と判定された指摘を誤りの種類ごとに集約した台帳。着手時と push 前に読む
- [[volume-split]] — 内側アーカイブを開いて中の巻の単位を子の巻として登録する「巻への分解」と、名前の巻範囲と中身の食い違いの検出。巻番号の候補の読み方・保存場所、読書位置の引き継ぎ、重複を食い違いにしない理由
- [[work-grouping]] — 作品の名寄せ(フェーズ 3)。巻の名前から作品を派生させ、末尾の番号は同じ名前の組がそろっているときだけ巻番号として読む。別名・著者・統合の根拠を項目ごとの出所・手動フラグ・確信度つきで持つ。自動統合の基準、手動の決定を守る規則、欠け巻の数え方、却下・分けた組を戻さない理由
- [[work-search]] — 作品の全文検索と絞り込み(#56)。FTS5 trigram の索引を作品 1 件 1 行で持ち、変更はトリガーの「古い」印で次の一覧の前に追いつかせる。正規化は名寄せと同じ。2 文字以下は LIKE、trigram の無い SQLite は普通の表。絞り込みは work_fields の項目名で汎用

## 未作成ページ (リンクだけ存在する / これから書く)

2 つの役割を兼ねる節。

1. 他ページから `[[...]]` で参照されているが実体が無いページの控え。次に書くべきページの候補リスト
2. **これから作るページ名の予約。** 複数セッションが同時に走る場合、実体を書く前にここへ名前を
   控えておかないと、同じ概念のページが別名で二重に作られる。着手時にこの節を読み、
   予約済みの名前と衝突していないか確認する

実体を作ったらこの節から消す(消し忘れは lint が落とす)。
