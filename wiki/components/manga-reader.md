# 漫画リーダー(manga-viewer)

漫画(`format` が `images`)の巻を `#/read/<id>` で開く画面。#136 で自作のリーダーから、tokagemushi 氏の
[manga-viewer](https://github.com/tokagemushi999/manga-viewer)(MIT、依存なしの素の JS、Shadow DOM に描く)へ置き換えた。
利用の旨は作者へ通知済み(利用者による)。ライセンス表記は `frontend/THIRD_PARTY_NOTICES.md`。小説は対象外で [[novel-reader]] のまま。

## 責務

- ライブラリがする: ページ画像の表示・右綴じ・縦長は単ページ / 横長は見開きの自動切替・ピンチズーム・慣性つきスワイプ・キー操作・先読み・
  ヘッダーとページスライダー・ヘルプ・「続きから読みますか?」の確認・しおりの画面
- SpineBox 側がする: 巻情報の取得と読み込み待ち・取得失敗の表示(`Reader()`。従来どおり)、読書位置のサーバー保存と再開位置の受け渡し、
  しおりの保存先(サーバー)、巻のブックマーク(★。[[bookmarks]])と次の巻(#113)のボタン、戻る先、
  ページスライダーの大きさと「最後の画面からさらに進むと次の巻へ」(#324。どちらもライブラリの外から足す)

## 決めたこと(コードからは理由が読めないもの)

- **ライブラリは npm の 0.6.0 ではなく GitHub のコミット `db5d7c8` に固定する。** npm の 0.6.0 は、初期化中の表示更新が先に
  `localStorage` の進捗を 1 ページ目で上書きしてから再開の確認を探すため、「続きから読みますか?」が出ない(jsdom で本物を組んで再現)。
  修正(`_progressRestored`)は main に入っているが未リリースだった。`package.json` はコミットの完全な SHA で指し、
  `package-lock.json` の `resolved` は `git+https://` にした(npm が書く `git+ssh://` のままだと、SSH 鍵の無い CI・サーバー機の `npm ci` で落ちうる)。
  修正入りの版が npm に出たら版指定へ戻してよい
- **再開位置はサーバーの読書位置を正とし、ライブラリへは `localStorage` 経由で渡す。** ライブラリは `storageKey` の
  `{slotIndex, pageIndex, timestamp}` を見て確認を出すので、開く直前に鍵 `spinebox.progress.<巻 id>` へサーバーの `progress.page` を書く
  (0 なら消す)。端末ごとの `localStorage` だけに任せると、スマホで読んだ続きを PC で開けない
- **確認に答えるまでと構築中はサーバーへ保存しない。** ライブラリは構築の途中で `onPageChange(1)` を呼ぶ。これを送るとサーバーの位置が
  0 ページで上書きされ、別の端末の再開位置が消える。構築が終わるまで(`ready`)と、Shadow DOM に `.mv-resume-dialog` がある間は捨てる。
  「最初から」を選んでもページを送るまでは送らないので、サーバーの位置は次のページ送りで上書きされる
- **既読は `onComplete`(最後の画面に着いた)で立て、前へ戻っても既読のまま送る**(従来と同じ。デバウンス 800ms、`pagehide` / 裏に回る / 画面を離れるときは即送信)
- **しおりはサーバーに置く(端末間で共有)。** 利用者と決めた。ライブラリの既定は `localStorage` だが、スマホと PC で読む使い方では端末ごとに分かれ、
  ブラウザのデータ削除で消える。`bookmarkApi` に `/api/page-marks` を渡し、`bookmarkId` は巻 id(ライブラリはこれを `work_id` という名前で送る。
  SpineBox の作品 id ではない)。ページは DB では読書位置と同じ 0 始まり、API だけ 1 始まり
- **しおりの題は保存しない。** ライブラリは常に既定の「ページN」を送り、書き換える手段が無い。保存すると、巻への分解・整理でページ番号が変わったときに
  古い番号の題が残るので、返すときに作る
- **しおりは利用者の記録として扱う。** オフラインでも付け外しでき、行は消さない。整理(CBZ 化・改名)ではブックマークと同じく**移し**、元に戻すと戻る
  (`organizer.py transfer_volume_state()` から)。巻への分解では読書位置と同じく親の行を残したまま子へ**写す**([[volume-split]])。
  整理で置き換わった巻・missing の巻も id を指せば読み書きできる(404 にしない。記録を消さない側に倒した)
- **ライブラリの「ブックマーク」は「しおり」と呼ぶ。** SpineBox のブックマークは作品・巻の印(#86)で別物。追加ボタンの文言を
  「現在のページにしおりを挟む」に差し替えた(`messages.bookmarkAdd`)
- **ヘッダーは 戻る・しおり・★(巻のブックマーク)・次の巻・全画面・ヘルプ。X 共有・リンクのコピーは出さない**(LAN 内のアプリ)。
  全画面はライブラリが PC 幅だけで出す。★ のボタンは構築時に作られるので、付け外しのたびに Shadow DOM の中のボタン(`.spinebox-volume-bookmark`)の
  `title` / `aria-label` / `aria-pressed` / アイコンを直接直す
- **次の巻へは、ヘッダーのボタンと「最後の画面からさらに進む」の両方で移る(#324)。** #136 ではボタンだけだった(ライブラリは最後のページより先へ進む操作を外へ渡さない。
  `onComplete` は最後の画面に着いた時点で呼ばれ、そこで移動すると最後のページを読めない)が、利用者はボタンに気づかず「動いていない」と受け取った。
  `watchPastEnd()` が、生成したインスタンスの内部メソッド 2 つを包んで拾う: キー・ホイール・スワイプ・ズーム中の端の引っ張りは `_goNext`、タップは `_navigateTo(今 + 1)`
  (タップだけ `_goNext` を通らないので両方要る)。ライブラリのソースは変えていない。内部名に頼るので、形が違えば何もせず(ボタンは残る)、
  固定したコミットを替えて形が変わったら `realViewer.test.ts` が落ちる。**最後の画面に着いてから 500ms(`PAST_END_SETTLE_MS`)以内の「さらに進む」は数えない。**
  ホイール・トラックパッドの慣性や連打で、最後のページを見る前に次の巻へ飛ぶため。続きから読むかの確認が出ている間も移らない。
  次巻がオフラインなら理由を出し、次巻が無ければ何もしない
- **ページスライダーは軌道 12px・つまみ 32px・押せる高さ 44px にする(#324)。** ライブラリの既定(軌道 6〜8px・つまみ 18〜22px)はタブレットで押しにくいという利用者の報告。
  `styles.css` は Shadow DOM に届かず、ライブラリに大きさのオプションも無いので、`enlargeSlider()` が生成後の Shadow DOM へ `<style>` を 1 つ足す。
  ライブラリ自身の規則(メディアクエリの中を含む)に勝つよう、セレクタはクラスを重ねて詳細度を上げてある。入力欄の背景だった軌道は疑似要素へ移した
  (入力欄を 44px にして押せる範囲を取るため)。ライブラリが消していたフォーカスの輪郭も戻した。小説の区切りのスライダーも同じ寸法(`styles.css` の `.reader-bar input[type="range"]`)
- **戻る(「<」)は巻の作品のタイトル一覧へ(#324)。** #136 まではホームだったが、巻はタイトル一覧から開くので、読み終えて戻ると作品を探し直すことになった。
  巻情報の `work_id` から `readerBackHref()` で決め、作品に割り当てられていない巻はホーム。作品の管理ページ(`#/works/<id>`)ではなくタイトル一覧にしたのは、巻を開く元がそちらだから
- **「横長画面で見開き」の切替は廃止した。** ライブラリは横長で常に見開き、縦長で単ページにし、横長で単ページに固定するオプションが無い
  (README の「単ページ」はこの自動切替のこと)。内部メソッドを継承で差し替えて残す案は利用者が選ばず、廃止した。
  「表紙を単独で表示」は `firstPageSingle` に渡し、次に巻を開いたときから効く(管理の好みタブ)
- **テーマは開いた時点のライト/ダークを渡し、読んでいる途中では作り直さない**(作り直すとページが戻る)

## 却下した代替案

- **npm 0.6.0 のまま、再開の確認の代わりに保存位置へ黙って `goToPage` する:** 利用者が求めた「続きから読む」の確認が出ないので採らなかった
- **しおりをライブラリ既定の `localStorage` に置く:** 端末ごとに分かれる(上)
- **ライブラリのソースを改変して同梱する:** 更新の取り込みで差分管理が要る。改変せず、オプションと Shadow DOM の外からの結線だけにした

## 落とし穴

- ライブラリの UI は Shadow DOM の中で、`frontend/src/styles.css` も DADS のトークンも届かない(配色・フォーカスリング・ターゲットの大きさはライブラリのまま)。
  SpineBox の画面の値([[frontend]])が効くのは SpineBox 側の読み込み待ち・取得失敗・通知の表示まで
- jsdom には `matchMedia` が無いので、本物のライブラリを組むテスト(`realViewer.test.ts`)は `matchMedia` と `ResizeObserver` を差し替える。
  それ以外のリーダーのテストはライブラリをモックしてオプションと結線だけを見る(`Reader.test.tsx`・`App.test.tsx`)
- ページ画像の読み込みはライブラリ任せで、横長で初めて開いた見開きは画像が来るまで数秒黒いことがある(従来の「読み込み中」の重ね表示は無い)。
  巻情報の取得中の「読み込み中」と 1.5 秒後の補足(#26)は `Reader()` に残っている
- モック API(`npm run dev:mock`)の `/api/page-marks` は `frontend/src/mock/mockBackend.ts` のメモリ上にある

## 確認したこと

- #136: 開発機で `_参考/` ではなく一時フォルダのサンプル(ライブラリのデモ画像を 12 ページと 9 ページの zip 2 巻にしたもの)を蔵書にして実バックエンドを起動し、
  組み込みブラウザの 375px で、6 ページ目の読書位置の巻を開く →「続きから読みますか? 6ページから続行」が出て、答える前はサーバーの位置が変わらない →
  続きからで 6/12 → 1 ページ送ると位置 7 ページ目がサーバーへ → しおりボタンでしおりがサーバーに入る → ★ でブックマークが付く → 次の巻へで 2 巻(1/9、確認なし、次の巻ボタンなし)。
  1280×800 では 6-7 の見開きが右綴じ(6 が右)で出て、戻るで一覧へ戻った。好みタブに見開きの項目が無いことも確認
- #324: モック API(`npm run dev:mock`)を組み込みブラウザの 820×1100 と 375px で開き、スライダーが太く・つまみが大きく出て入力欄の高さが 44px であること、
  2 巻の最後の画面(8/8)で左矢印を押すと 3 巻(`#/read/3`)が開くこと、「<」で `#/works/1/titles` へ移ることを確かめた。タッチ端末(実機のタブレット)では未確認
