# 受け入れ(受け入れフォルダ → 承認で書庫へ)

新しく手に入れた本を置く**受け入れフォルダ**を設定し、同期で検出して、書庫のどこに何という名前で入るかを
プレビューし、利用者が承認したものだけを書庫へ入れる(GOAL.md フェーズ 4)。入れる処理は新しく作らず、
[[organize]] の仕組み(`kind="intake"`)をそのまま使う。自動では何も動かさない。

## 責務

- する: 受け入れフォルダの検出(同期)、1 ソースごとの整理案(分類・出力先・理由)、承認、承認した巻の作品への割り当て
- しない: ファイルの移動・CBZ 化そのもの([[organize]] の `execute` / `undo`)、重複の自動解消、
  受け入れ待ちの本を蔵書(一覧・作品・検索・重複・結線)に数えること

## 入口となるファイル

| パス | 役割 |
| --- | --- |
| `spinebox/organize/intake.py:78 Intake` | 整理案(`evaluate`)、一覧・プレビュー(`list_items` / `preview`)、承認(`approve`)。`Decision` が利用者の選択(作品・新しい作品名・番号・取り込まない・見た出力先) |
| `spinebox/config.py:73 InboxSetting` | 設定 `inbox_dirs`(受け入れフォルダと、入れる書庫の組)。検証は `_inboxes()` |

| `spinebox/organize/organizer.py:352 execute` ほか | `kind="intake"` の実行・元に戻す(`execute` の `mode="move"`、`_undo_move_in`) |
| `spinebox/app.py:925 inbox_list` | `GET /api/inbox`・`POST /api/inbox/sync`・`/preview`・`/approve` |
| `frontend/src/organize/Inbox.tsx:243 Inbox()` | 画面(`#/inbox`)。同期 → 項目ごとの整理案 → 作品・番号・取り込まないの選択 → 承認 → 履歴から元に戻す |

## 流れ

1. **同期**(`POST /api/inbox/sync`)。受け入れフォルダを蔵書と同じスキャナーで走査して `library_roots.inbox = 1` の行・巻として
   DB に記録する。読み取りだけで、内側アーカイブは取り出さない。受け入れフォルダの巻は一覧・作品・検索・重複・結線の対象にならない
2. **プレビュー**(`GET /api/inbox` は目次を開かず記録だけ、`POST /api/inbox/preview` は選択を反映して目次まで読む)。何も書かない。
   1 ソースごとに次のどれかに分類する: 既存作品の巻 / 新しい作品 / 作品が決まらない / 既に持っている巻の疑い / 読めない(壊れたアーカイブなど) / 対象外。
   状態は `ready`(そのまま承認できる)・`choose`(利用者の確認が要る)・`blocked`(取り込めない。理由つき)
3. **承認**(`POST /api/inbox/approve`)。選んだ項目を 1 件ずつ実行する。失敗した項目は巻き戻し済みで、受け入れフォルダに残り、
   ほかの項目は止めない。承認しなかったものは次の同期でも出る
4. 履歴(`#/organize`)から元に戻せる。元に戻すと本は受け入れフォルダに戻り、また受け入れ待ちに出る

## 取り込み方(`mode`)

- `move`: 1 巻 = 1 つの CBZ ファイル、または小説(EPUB・テキスト)。**中身を変えずに書庫へ移すだけ**(`move_no_overwrite`)
- `cbz`: それ以外(zip・7z・rar・画像フォルダ・複数巻のまとめ)。巻ごとに 1 つの CBZ にして書庫へ([[organize]] の CBZ 化と同じ検証)
- 出力先は命名テンプレート(`[organize] name_template`)。既定は `<作品名>/<作品名> 第NN巻.cbz`

## 自動で決めず、確認を求めるもの(`choose`)

ファイル名・フォルダ名は候補にすぎない(`CLAUDE.md`「蔵書を扱う不変条件」)ので、次は利用者が選ぶまで承認できない。

- **作品が決まらない。** 巻自身の名前から作品名を読めず、外側のフォルダ名などから推測したとき。または、
  名前が似ている(`SIMILAR_MIN` 以上)既存の作品があるとき(別の作品かもしれない)。近い作品を候補として出し、
  「その作品に入れる」か「新しい作品名」を選ばせる
- **番号が読めない巻**(`number` が無い)。番号を入力させる(`MAX_NUMBER` まで)
- **書庫に同じ作品・同じ番号の巻が既にある**(重複の疑い)。取り込まないか、番号を直す。名前の番号が同じでも
  別の巻かもしれず、見た目の指紋の比較までは行っていない(下の「却下した案」)
- **一覧に見える巻を持たない作品は、作品の候補にも「既にある作品」にもしない**(`_drop_unlisted_works`)。承認を元に戻すと、入れた巻は
  外れても作品の行は残る(レコードは消さない)。それを候補にすると、同じ本を同期し直したとき「同じ名前の作品が複数」と確認を求め、
  作品の一覧に出ない作品を選ばせることになる(実データの往復で見つけた)
- 入れた巻の作品への割り当ては、利用者が選んだなら手動の決定にする(再計算で戻さない。[[work-grouping]])。
  自動のものは、名前からの割り当てが狙った作品になっているかを確かめ、違えば付け替える。
  新しい作品名を選んだときは、巻の名前から同じ作品名の作品が既にできていればそれを手動の割り当てにする(`_assign`。
  新しく作ると同名の空の作品が残る。これも実データで見つけた)

承認は、プレビューで見た出力先(`expect_outputs`)を一緒に送る。承認の時点で出力先が変わっていたら実行しない
(その間に書庫の同じ名前の巻が増えた場合など)。

## 安全設計

`organize.md` の規則に加えて、受け入れ固有の理由を残す。

- **受け入れフォルダの本は同期・プレビューで一切動かさない。** 動かすのは承認だけで、元は受け入れフォルダの退避
  (`<受け入れフォルダ>/.spinebox/trash/<操作ID>/original/...`)へ移すだけで消さない。作業場は書庫側
  (`<書庫>/.spinebox/work/`)に置き、書庫への確定は改名にする。**受け入れフォルダと書庫が同じドライブでなければ、
  同期の画面・計画・実行直前の三重で止める**(別ドライブの「移動」はコピー + 削除になり、途中で落ちると半端になる)
- **受け入れフォルダと書庫は重ねられない**(設定の読み込みで拒む)。書庫の中に受け入れフォルダがあると、
  スキャンが受け入れ待ちの本を蔵書に数えてしまう。ドライブが同じかは、ドライブが見えない間もあるので設定では見ず、
  同期・承認のときに確かめる
- **オフラインのときはレコードを消さない。** 受け入れフォルダ・書庫のどちらかが見えないときは、その旨を理由に出して
  取り込めないとするだけ。書庫が一度もスキャンされていないときも同じ(出力先の既存の巻と突き合わせられないため)
- **元に戻すとき、書庫で付いた作品の割り当て・読書位置を受け入れ側へ写し戻さない。** 受け入れフォルダの巻は
  受け入れ待ちの行で、写すと作品に入ってしまう(`_record_undone` が `kind="intake"` を除く)。元に戻すのは、移した先の
  ファイルが承認時のまま(サイズ・mtime)で、受け入れフォルダの元の場所が空いているときだけ。元に戻した後の作品への
  割り当ては取り直す(`organize_undo` が `_sync_works`)
- **スキャンの問題(`scan_issues`)は受け入れと書庫で分ける。** 受け入れフォルダの走査が書庫の問題表示を消さず、
  書庫の走査が受け入れの問題を消さない(`collect_issues(inbox=...)`)
- 名前が以前に受け入れた本と同じ(`organized_op_id` が立っている)ものは、履歴で元に戻すか名前を変えるまで承認させない

## 却下した案

- **自動で承認する(確信度が高いものだけ)。** GOAL.md が「承認で書庫へ」と定めている。自動で決められる範囲を広げるのは、
  実際の誤りを見てからにする
- **受け入れフォルダの本も蔵書に数え、一覧で「未整理」の印を付ける。** 一覧・作品・重複・結線に未整理の本が混ざり、
  欠け巻や重複の判定が揺れる。`library_roots.inbox` の 1 列で全部から外せる今の形のほうが漏れにくい
- **別ドライブの受け入れフォルダをコピー + 削除で受け入れる。** 蔵書を壊さないための前提(確定が改名)を崩す
- **重複の判定に見た目の指紋(dHash)を使う。** 受け入れの本は蔵書として解析されていないので、指紋のために全ページを
  読むことになる。今は名前から読んだ番号の突き合わせまで。精度を上げる案は別 Issue

## 落とし穴

- `LISTED_VOLUMES_JOIN/WHERE` が「見えている巻」の唯一の条件。受け入れの巻を除く `r.inbox = 0` はここにあるので、
  巻を数える新しいクエリはこの条件を使う(使わないと受け入れ待ちの本が蔵書に混ざる)
- 書庫のスキャンが済んでいないと承認できない。受け入れ側の画面は先に書庫をスキャンするよう案内する
- 承認の API は 1 件ずつの結果(`results`)を返す。HTTP が成功でも項目ごとに `ok: false` がありうる
- 同期と承認はスキャンと同じロックで直列化する(`/api/scan` と同時に走ると 409)
- `tests/test_search.py` のマイグレーション数の検査は `>= 9`(件数を固定すると、列を足すたびに壊れる)

## 経緯

- 実データの往復(`_参考/サンプル本` を同じドライブの一時ディレクトリへコピーし、書庫にかくかくしかじかの 7z、受け入れフォルダにお気楽領主の zip・かくかくしかじかの 7z の再入手(コピー)・壊れた zip を置いた。原本は処理対象にしない): 同期で 4 通りが出た。お気楽領主の zip は新しい作品(同名の出力になる 2 巻と作品名の揃わない巻があり確認が要る)、かくかくしかじかの再入手は全巻が既に持っている巻の疑い、壊れた zip は取り込めない(理由つき)。再入手の 7z は内側アーカイブの中の巻を調べるまで承認できない(「中の巻を調べる」で取り出し先は展開キャッシュだけ。受け入れフォルダは変わらない)。再入手の 1 巻を第05巻に直して他を取り込まない・お気楽領主の同名 2 巻を取り込まないにして 1 件ずつ承認し、書庫の一覧・作品・ページ表示に出ること、承認しなかった壊れた zip が受け入れフォルダに残ることを確かめた。元に戻した後、書庫と受け入れフォルダがパス・sha256・サイズ・mtime まで承認前と一致し(原本 2 ファイルもサイズ・mtime 不変)、同期し直しても最初と同じ整理案に戻る。この往復で、同名の空の作品が残ること・元に戻した後の作品が候補に出ることを見つけて直した(上の 2 項目)。画面では、別の本を承認すると、まだ承認していない本の選び直し・選択が消えていたのを直した(`Inbox()` の `reload`)

  パス・バイト列・mtime まで承認前と一致することをテストで確かめている(`tests/test_inbox.py`)。
  プレビュー・同期で何も書かないこと、4 通りの分類、承認しなかった項目が受け入れフォルダに残ること、別ドライブ・
