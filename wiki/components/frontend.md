# フロントエンド(`frontend/`)

蔵書一覧と、リーダー(漫画は外部ライブラリの manga-viewer を組み込んだもの。[[manga-reader]])。React + Vite + TypeScript。`npm run build` の出力 `frontend/dist` を
バックエンドが `/` で配信する。

## 責務

- する: 一覧(`GET /api/volumes`)・スキャンの起動(`POST /api/scan`)・巻の食い違いのバッジと説明・「中の巻を調べる」(`POST /api/volumes/{id}/analyze`)・重複候補の画面と一覧の印([[duplicate-detection]])・作品の一覧 / 作品ページ / 統合の提案の画面([[work-grouping]])・利用者の判断待ちを集めた確認の画面(#207。公開 DB の候補・統合の提案・重複の候補)・リーダー(巻情報の取得・読み込み待ち・取得失敗の表示と、読書位置の保存と再開の結線。表示は [[manga-reader]] / [[novel-reader]])・整理(CBZ 化)のプレビュー → 実行と、履歴からの元に戻す・範囲指定の整理(テンプレートの入力・パラメーターのチップ・パスの例・CBZ 化もまとめて行う・プレビュー → 実行 → まとめて元に戻す)([[organize]])。表示設定(表紙単独)は端末ごとに `localStorage` へ
- しない: ページの並び順・ページ数・オフライン判定・巻番号と食い違いの判定。どれもバックエンドが決めた `pages[]`・`offline`・`findings` をそのまま使う

## 決めたこと(コードからは理由が読めないもの)

- **ファビコンは SVG・ICO・PNG の 3 種を `frontend/public/` に置く。** モダンブラウザ向けには高精細・ダーク/ライト対応のベクター `favicon.svg`、レガシー互換に 16/32/48px マルチサイズの `favicon.ico`、iOS Safari のホーム画面追加・PWA 向けに 180x180 の `apple-touch-icon.png` を用意する。Vite ビルド(`npm run build`)で `frontend/dist/` にそのままコピーされ、バックエンドの静的配信 `/` 経由でブラウザへ配信される

- **統合の根拠に、同じ公開 DB 項目への linked を出す。** `frontend/src/works/labels.ts:51 evidenceLines()` が
  `alias.shared_item` を「同じ公開データベースの項目「<取得元>」(<source_id>)に linked している」と表示する。
  確信度は元の別名の値(`alias_confidence`)を出し、0.9 に引き上げた理由を隠さない。文言だけで、画面の構造は変えない
- **ページ番号は 0 始まり。** `progress.page` も `pages[].index` と同じ番号で送る(画面の表示だけ +1)。
  #14 と同時に作ったため、契約の文面に始まりの番号が無かった。バックエンドと食い違ったら API 契約側を正にして合わせる
- **位置は「画面」ではなく「ページ」で持つ。** 回転で見開きの組み方が変わっても、読んでいたページを含む画面から再開できる。
  漫画の表示・見開き・操作はライブラリ([[manga-reader]])に任せた(#136 までの自前の見開きの組み方・タップの向きの規則は廃止。タップ/スワイプ/キーの判定 `layout.ts` は小説のリーダーが使う)
- **一度既読になった巻は、前のページへ戻っても `finished=true` のまま送る。** 読み返しで既読が消えないようにするため
- **保存は 800ms のデバウンスで最後の位置だけ。** 一覧へ戻る・タブが裏に回る(`pagehide`/`visibilitychange`)ときは待たずに
  `fetch(..., {keepalive: true})` で送る。スマホはタブを閉じずに切り替えることが多く、デバウンス中の位置が失われるため
- **次の巻へ移れる(#113)。** 次の巻はバックエンドが作品の一覧の並び(番号順 → 番号なしは名前順)から決める。同じ番号の重複は同じ巻として飛ばし、
  次の番号に重複があればその並びの 1 つ目を開く。次の巻がオフラインのときは移動せず「次の巻「<名前>」はオフラインです」を出す。
  小説は最終ページからさらに進むと移り、漫画はヘッダーの「次の巻へ」のボタンで移る([[manga-reader]])。移動の前に今の巻の位置(既読を含む)は後始末の `flush()` が送る。
  漫画と小説の両方が `frontend/src/reader/nextVolume.ts:10 nextVolumeStep()` を使う
- **画面の切り替えはハッシュ(`#/read/<id>`)。** バックエンドは `dist` を `/` で配信するだけでよく、深いパスを
  `index.html` へ振り向ける設定が要らない。ルーターのライブラリも入れていない。
  ただし共有されたリンクやブックマークが `/read/<id>`(パス)の形だと、バックエンドの SPA fallback で画面は開くがハッシュが空で一覧になる。
  そのため起動時に `frontend/src/route.ts:143 canonicalUrl()` が `/#/read/<id>` へ `replaceState` で直す(#19)
- **食い違いの説明はカードのリンクの外の `<details>` に置く。** リンクの中に置くと、説明を開くつもりのタップでリーダーへ飛ぶ。
  バッジ(「巻の食い違い」)はリンクの中。分解で作った子の巻には「「親の名前」の中」と出す。同じ食い違いは親の子すべてに出る([[volume-split]])
- **整理は一覧のカードの「CBZ に整理」から。** 押しただけでは計画(プレビュー)を作るだけで、蔵書は動かない。
  実行ボタンは計画が `planned` のときだけ出す(`blocked` は理由だけ出す)。サーバーの 409 の `detail` をそのまま見せる。
  プレビュー画面を確認の代わりにして、`window.confirm` は使っていない
  中の巻をまだ調べていない内側アーカイブを含むソースは `blocked` になり、「中の巻を調べて計画を作り直す」だけを出す(調べるのは明示操作で、プレビュー自体は解析しない。[[organize]])
- **テンプレートどおりの整理は作品ページの「この作品をテンプレートどおりに整理」から。** 全巻を変更前 → 変更後と
  改名・移動 / そのまま / 対象外 / 競合 / 整理しない、の札と理由で並べる。競合の巻の「この巻を整理しない」は計画を作り直すだけ
  (整理しない巻のリストを送り直す)。1 巻 = 1 CBZ でない巻には「テンプレートの名前で CBZ に整理」へのリンクを出す。
  これらの操作はプレビュー中だけ出し、履歴では出さない
- **範囲指定の整理(#84)のプレビュー結果は、要約 → 競合 → 実行ボタン → 実行する内容 → 整理しない内容のリストにする(#151)。**
  (`frontend/src/organize/OrganizeFiles.tsx` の `ClashGroups` / `RangeWork` / `RangeRest`)。競合は整理後の名前ごとに見出しを付け、候補を 1 行 1 件で並べる。
  行頭のチェックは既定でファイル数の多い方に入り、同数は未選択。行を選ぶと `exclude_volume_ids` を送り直し、選んだ行にフォーカスを戻す
  (組が消えたときは結果の見出し)。実行する内容は改名・移動と CBZ 化を別のリストにし、元/先は 768px 以上で 2 列、スマホは積む。
  整理しない内容は `<details>` にまとめる。要約は実行する / 競合 / 整理しない / 対象外 / そのまで、競合の中の「整理しない」は二重に数えない。
  呼称は「競合」「整理しない」「この巻(この本)を整理しない」。数が多くなる前提でカードではなく行リストにし、チェックは 24px + 行全体のタップ領域、
  フォーカスリングは行に出す。カード表示(#143 / #145)は廃止した。
  #153: 既定のチェックは、ほかの巻が譲った先(`superseded_by`)から決める(`keepOf`。選択待ちの巻にも入る)。1 件だけの競合は組にせず、整理しない内容の
  「実行できない」に理由つきで出し、そのときは `<details>` を開いておく。CBZ 化は元ごとにまとめて元のパスを見出しに 1 回だけ出す(`cbzBySource`)。
  結果のボタン列は sticky(スマホは上の帯 53px の下)。「CBZ 化した元を削除する」は CBZ 化を選んだときだけ出し、実行の前に確認のチェックを取る([[organize]])
- **範囲指定の整理(#84)の画面は「1. 対象 → 2. 名前の決め方(任意) → 3. プレビューして実行」の 3 段にする(#149)。** フォルダーテンプレートは
  「フォルダーへ振り分ける(任意)」の `<details>` に畳み、選択中のテンプレートを summary に出す。項目(`{title}` など)の差し込みは入力欄ごとの
  「項目を差し込む」に置き、最後にフォーカスした欄へ入れる規則は廃止した(フォルダー欄が閉じていても差し込み先が分かる)。
  よく使う設定は `applyTemplates()` が両方の欄へ入れ、フォルダーがあれば `<details>` を開く。プレビュー後は結果の見出しへフォーカスとスクロールを移し、
  要約(実行する / 競合 / 整理しない / 対象外 / そのまま)・競合の行選択・実行ボタン・実行内容・整理しない内容を 1 か所にまとめる。フォームは 800px に抑え、スマホの sticky な帯
  (約 53px)に隠れないよう `scroll-margin-top` を付ける。`<form>` にして Enter でもプレビューできる
- **整理のフォルダー選択はモーダルにする(#149)。** 今のパスから開き、パンくず(蔵書フォルダ全体 / 途中のフォルダ)で移動する。開いたら見出しへ
  フォーカス、Esc で閉じ、閉じたら開いたボタンへ戻す。Tab はモーダルの中を回す(`frontend/src/organize/OrganizeFiles.tsx:666 FolderPicker`)。
  前回のパスが読めないときはエラーを出して蔵書フォルダ全体へ戻す。テンプレートの誤りはプレビューを `disabled` で塞がず、押したら該当欄へ
  フォーカスする(DADS のフォーム)。処理中(プレビュー・実行・元に戻す)だけ入力欄を `disabled` にし、`aria-busy` を付ける
- **スキャンの結果は「N 巻を検出」と「読めなかったもの N 件」(開くと理由の一覧)を出す(#48)。** 件数が 0 なら出さない。
  サーバーの `issues` は最大 200 件なので、切った分は「ほか N 件は省略しました」と知らせる。スキャンが失敗したら、サーバーの `detail`
  (型とメッセージ)をそのままエラー表示に出す。固定の文言だけだと、サーバー機で何が起きたか画面から分からなかった
- **作品カードに別名は出さない(#103)。** 一覧のカードは作品名・著者・出版社・巻数・バッジだけを出し、
  別名は作品ページで見る(利用者の要望)。API(`GET /api/works` の `aliases`)・作品ページの別名の編集・統合の提案の表示はそのまま。
- **作品カードに種別・ジャンルと「重複」「統合済み」は出さない(#129)。** ホーム・漫画・小説のカードは作品名・著者・出版社に絞り、
  種別(漫画/小説)とジャンルはカードから外す(漫画・小説はナビで分かれ、ジャンルは作品ページで見る)。重複と統合済みは
  一覧の判断には使わず、カードが情報過多になるためバッジから外す(欠け・オフライン・読書状態は残す。統合の提案・候補の確認待ちは #210 で通知ドットに替えた)。
  巻数は独立した行ではなく `.work-badges` の先頭のタグにし、文言を「既刊8巻(〜6巻)」(最高巻数が無ければ「既刊8巻」)にした(#185)。「既刊」は手持ち分(`GET /api/works` の `volume_count` = 見えている巻の数。`max_volume` は手持ちの最大巻番号)で、公開 DB の全巻数 `total_volumes` ではない(`WorkLinks.tsx` の候補の「全 N 巻」はそちら)。
- **欠けの番号は多すぎるときだけ件数にする(#165)。** 作品カードのバッジと作品ページの「欠けている巻」は、欠けが
  5 個以下なら番号を並べ(「3・5 巻」)、6 個以上なら「12 巻」と件数だけにする。全番号は title 属性に入れ、
  カーソルを合わせるとツールチップで出る。欠けの多い作品でカードが数行になり、一覧が読みにくくなるのを避ける。
  DADS v2.18.2 にツールチップのコンポーネントが無いのでブラウザ標準の title を使う(件数は常に見えるので、
  内訳は補助)。組み立ては frontend/src/works/labels.ts:40 missingLabel()。
- **作品カードに表紙を出す(#75。[[cover-thumbnails]])。** カードの横幅いっぱい(`.work-card .work-cover` で幅 100%・2:3 の縦横比・上角丸)に置き、
  文字は表紙の下へ続ける(#129)。`cover_volume_id` の巻の縮小画像を `<img loading="lazy">` で取り、
  読み込めたら見せる。表紙が無い・404(入れ子の巻でまだ作っていない・小説・1 ページ目が画像でない)なら
  「表紙なし」の枠(`WorkCoverPlaceholder`)を同じ 2:3 で残す(#132)。枠を残すのは作品カードだけで、
  タイトル一覧・ブックマークの表紙は今までどおり何も出さない。表紙の枠を全カードに出すので、同じ行の
  タイトルの開始位置はそろう。カードの高さは中身に合わせ、一覧全体で揃えない(#161。`grid-auto-rows: 1fr` は
  グリッドの高さが不定のとき全行を一覧で一番高いカードに揃えるため、バッジの少ない作品ほど内側の下に余白ができた。
  `.work-grid` は `align-items: start`)。入れ子の巻の表紙は管理のスキャンと補完タブの「表紙のみ補完」(明示操作)で作る。
  表紙の URL は `ETag` + `Cache-Control: private, no-cache` なので、画面を開き直すと取り直す(以前の「表紙を作る」の後に `?rev=` を変える仕組みは、作成を画面から起動しなくなったので廃止した)。
  巻の一覧のカードには出していない(要望は作品の一覧。同じ `api.thumbnailUrl()` で足せる)
- **巻情報の読み込み待ちを見せる(#26)。** 入れ子のアーカイブ(7z の中の rar)を初めて開くと、`GET /api/volumes/{id}` が内側を
  取り出す間(実測 3〜8 秒)何も出ず、黒い画面のままで読み込み中と分からなかった。巻情報の取得中はリーダーの黒い枠の中央に
  スピナーと「一覧へ戻る」を出し、1.5 秒(`SLOW_HINT_MS`)を超えたら「初めて開く巻は展開に数秒かかる」と補足する。
  巻情報が来た後のページ画像の読み込みは、漫画はライブラリ任せ(#136 までの「読み込み中」の重ね表示と、それに伴う #51 の React #185 の対処は自前のリーダーごと無くなった)
- **取得失敗の文言は HTTP ステータスで分ける。** 404 は「蔵書から無くなった」、409 は「オフライン」、422(壊れたアーカイブ・
  展開上限超過)はバックエンドの `detail` をそのまま出す。理由はバックエンドしか知らないため。どの失敗でも一覧へ戻るリンクを出す
- **重複候補の画面は何も消さない。** 見比べて「重複ではない」を付けるだけで、削除・移動のボタンは置かない(重複の解消は CBZ 化の整理の役目)。2 巻の表紙は 1 ページ目の画像(`api.pageUrl(id, 0)`)で、
  別スキャンは 1 ページ目が口絵と表紙で食い違うことがあるので、バックエンドが返す一致ページの例(最大 3 組)も並べる。375px では 2 巻を 2 列のまま、項目名を値の上に積む
- **一覧の印「重複の候補あり」は巻のリンクの外**(食い違いの説明と同じ理由)。押すと重複候補の画面へ行く
- **汎用カルーセルライブラリは使わない**(GOAL.md の初期既定)。ページ送りは状態の差し替えだけで、アニメーションは無い
- **小説は同じ `#/read/<id>` で開き、巻情報の `format` でリーダーを切り替える。** 一覧のカードには「小説」の印と「EPUB / テキスト」を出し、
  ページ数・「CBZ に整理」は出さない。読みかけは「読みかけ(区切り / 区切りの数)」(ページ数は文字サイズで変わるので出さない)。
  文字サイズは端末ごとに `localStorage` の `spinebox.novel` へ([[novel-reader]])

- **作品ページの「手で直した項目」は出所を明示する。** 作品名・著者・別名・巻の割り当てごとに「手動で編集 / ファイル名から(確信度 90%)/ 重複候補の証拠で統合」を出す。名寄せは名前の推測なので、利用者が根拠を見て直せるようにするため。
  提案は確信度と根拠(一致ページ数)を見せ、承認するまで統合しない。統合の提案の画面には「作品名・著者で探す」の欄があり(#208)、300ms 待ってからサーバーへ `q` で問い合わせ、後から出した要求の結果を古い応答で上書きしない。0 件のときは絞り込み中かどうかで文言を分ける。モック API も同じ部分一致で絞る。
  カード(#243)は作品名・巻のファイル名がとても長い(著者の角括弧+作品名+巻)前提で、同じ長い名前を繰り返さない: 巻は番号の札(「1巻 ×2」。同じ番号は数でまとめ、番号の無い巻は作品名とその前を落とした短い名前)にし、ファイル名の一覧は出さない。
  別名は両方の作品名と空白・大小文字しか違わないものを落として 1 件だけ見せ、残りは「ほか N 件」で折りたたむ。2 つの作品名が近い(共通の頭と尻が短い方の半分以上)ときは違う部分を `<mark>` で強調する(「…件」と「…件c」のような 1 文字違いを探させない)。
  根拠の文は一致した名前を 1 回だけ書き、自動統合の基準(90%・手動の作品は常に確認待ち)の説明はカードごとに繰り返さず一覧と作品ページの上に 1 回だけ出す。375px では 2 作品を縦に積む。
  巻の付け替えは巻のチェックボックスで選んで「新しい作品に分ける」/「この作品へ移す」(手動の決定になり再計算で戻らない)
- **ジャンル・タグ・出版社・候補はサーバーが日本語にして返すので、画面では訳さない**(#74)。あらすじは #82 で廃止し、作品ページに表示・編集の欄を置かない([[metadata-linking]] の「あらすじの廃止」)
- **作品一覧の検索と絞り込みは、スマホ幅で 1 行に収める。** 検索欄と「絞り込み」ボタンの 1 行だけを常に出し、読書状態・著者・種別・ジャンル・タグの選択はボタンで開いたときだけ出す(開いていなくても選んだ数をボタンに出す)。候補の無い項目(公開 DB の情報がまだ無い作品だけのときの種別・ジャンル・タグ)は選択欄ごと出さない。種別の候補は `manga` / `novel` で届くので `KIND_TEXT` で漫画・小説と表示する。検索語は打鍵ごとに引かず 250ms 待ってから引き(`SEARCH_DELAY_MS`)、後から出した要求の結果を古い応答で上書きしない。絞っているときは「N 件 / 全 M 作品」と「条件を消す」、0 件なら「条件に合う作品がありません」(蔵書が空のときの文言と分ける)。モック API の検索は `frontend/src/util/normalize.ts:2 normalizeSearch()` でバックエンドと同じ正規化を真似ている
- **公開 DB の値は項目ごとに出所を出す。** 「公開データベース: 国立国会図書館サーチ(確信度 100%)」「手動で編集」など。確認待ちの候補は「これを採用」を押すまで反映しない(候補は種別・出版社・巻数・一致度つきで、同じ名前の漫画と小説を見分けられるように採用ボタンの名前にも種別を入れる)。
  取得元が落ちているときは理由を出し「すでに入っている値はそのまま」と添える。NDL の候補を選んで種別が決まったら、保留だった取得元を保存済みの応答で連携し直す(通信は出ない)。国立国会図書館サーチの利用明示のため、作品の一覧と作品ページの末尾に利用元を出す([[metadata-sources]])
- **ホーム(`#/`)は作品の一覧。** 巻の一覧(`#/volumes`)は廃止し、ホームへ戻る。#85 までは `#/` が巻の一覧だったので、リーダー・整理の画面の「一覧へ」(`libraryHref`)はホームへ戻る。`#/works` もホームと同じ画面
- **作品カードは「タイトル一覧」(`#/works/<id>/titles`)へ、管理はそこから(#105)。** カードの行き先を作品ページから分け、まずその作品の巻を番号順に並べる。「作品を管理」ボタンで今までカードから開いていた `#/works/<id>`(作品名・著者・巻の割り当て・統合)へ移る。
  管理ページの URL を変えないのは、ブックマーク・フォロー・統合の提案・整理の履歴からの既存のリンクをそのまま使うため。作品ページの戻り先は「タイトル一覧へ」にした
- **タイトル一覧の行の名前は「作品名 第N巻」にそろえ、ファイル名を出さない(#115)。** 同じ作品でも巻の名前は元のファイル名のまま(英字・作者の括弧・アンダースコア)で揺れ、並べても同じ本の巻に見えない。補完済みの作品名(`work.title`)と巻番号から作り、番号の無い巻だけ元の名前を残す(作品名だけでは見分けられない)。
  進み具合は「N% (読んだ / 全体)」にし、「未読」の文字は行に出さない(未読は 0% と色で分かる)。表紙は行の一番左に置き、並んだときに背表紙のように見えるようにする。色は読書状態(未読 / 読書中 / 読了)で塗り分け、凡例を出す。ヘッダーには作品全体の進捗(ページの割合と読了巻数。重複は 1 巻として数える)を出す。ページ数が未確定の巻(まだ開いていない小説)は割合に数えず、その巻数を添える。
  行頭の「N巻」の列は置かない。巻名「作品名 第N巻」に番号が含まれ、列が冗長なため。重複モーダルの見出し「N巻 の重複」など番号の表示は残す
- **重複した巻は 1 行にまとめ、押したらモーダルで選ばせる(#115)。** 同じ巻番号の別スキャンは同じ本なので、行を分けると持っている巻の数と全体の進捗が水増しされる。行の代表は読んでいる巻(読了 > 読書中 > オフラインでない巻)にし、押すと `#/read/<id>` を選ぶモーダルを出す。モーダルでは元の名前を出す(名前の揺れが選ぶ手がかりになる)。「重複」の印は残す。Esc で閉じ、閉じたら開いた行へフォーカスを戻す。Tab はモーダルの中を回す(背後の行へフォーカスを移さない)
- **欠け・最新巻はフォローの「続刊を調べる」の結果だけを使う(#115)。** タイトル一覧を開くたびに公開 DB を引き直すと、閲覧の画面が取得元の遅さ・失敗に引きずられる。`work.follow.releases`(フォロー中で、最後に調べた結果)があるときだけ、点線の行で番号の位置(欠け)と後ろ(最新巻)に出す。持っていないので押してもリーダーへは行かせない
- **利用者の判断を待っているものは「確認」(`#/review`)に 1 か所に集め、処理を動かす・設定するものは管理に置く(#207)。**
  公開 DB の候補は作品ページで 1 件ずつ、統合の提案は `#/works/proposals` と管理の「統合」タブの 2 か所、重複の候補は管理のタブの外(`#/duplicates`。開くと管理のタブが消え、戻り先がホーム)にあり、
  作業中に作品ページ ⇔ 一覧を行き来していた。旧 URL は `parseRoute()` で確認のタブへ振り替える(ブックマーク・一覧の印のリンクを壊さない)。
  サイドバーと各タブの件数は `GET /api/review/counts` で、画面に出るものだけを数える(開いても何も出ない件数を出さない。[[backend]])。画面が変わるたびと、確認の画面で何かを決めたときに取り直す。
  ホームの帯は「統合の提案が N 件」から「確認待ちが N 件」(3 種の合計)へ。作品ページでの公開 DB の候補の選択も残す
- **作品ごとの確認待ちは、カードでは通知ドット 1 つ、作品ページ・タイトル一覧では確認の該当タブへのリンクにする(#210)。**
  カードの「統合の提案」「候補の確認待ち」の文字のタグは、欠け・読書状態と並んで情報過多だったので、表紙の左上に `--warn`(オレンジ)のドットを 1 つ重ねる形にまとめた。
  色と形だけに頼らないよう、ドットは `role="img"` で「確認待ちあり(統合の提案・公開DBの候補)」を読み上げ名とツールチップに持つ。表紙の画像の上でも見分けられるよう `--card` の縁を付ける(強制カラーでは `Mark`)。
  カードはタイトル一覧へ開くので、案内 `frontend/src/works/ReviewPending.tsx:37 ReviewPendingNotice()` は作品ページとタイトル一覧の両方の上部に出し、種類ごとに `#/review/proposals` / `#/review` へリンクする。
  #207 で作品ページの「公開データベース」節に置いた 1 行は、同じリンクが 2 つ並ぶので上部の案内へまとめて外した。重複の候補は巻単位で `GET /api/works` に作品ごとの数が無いので、ドットの対象にしていない
- **公開DBの候補タブは、作品ページを開かずにその場で選ぶ(#207)。** 1 作品 1 枠で表紙・作品名・巻数と、確認待ちの取得元だけの `WorkLinks` を出す(連携済み・該当なしは作品ページで見る)。
  選び終えた作品は一覧から消さず「確認済み」に畳む(詰めると直後のタップが次の作品のボタンに当たる)。押したボタンが消えるので、次の確認待ちの見出し(最後ならその行の見出し)へフォーカスを移す。
  NDL を選ぶと保留だった取得元が保存済みの応答で決まるので、その間は「反映しています…」を出す
- **候補の選択は作品をまたいで 1 件ずつ順に流し、結果は最新の一覧へ入れる(#254)。** 続けて押すと、反映中に押した作品の結果で先の作品が確認待ちに戻っていた
  (押した時点の一覧を閉じ込めたまま書き戻していた)。待っている作品には「順番待ち…」を出す。選び終えたら次の確認待ちの作品へスクロールする(`prefers-reduced-motion` では動きなし)
- **候補は行全体を「これを採用」の押せる範囲にし、先頭に漫画・小説のタグを出す(#254)。** 小さいボタンが押しにくいという要望。ボタンの `::after` を行いっぱいに広げる形で、
  ボタン自体は 1 つのまま(行を `<button>` にすると中の「出典を開く」リンクが入れ子の操作になる)。リンクは `z-index` で上に出して押せるようにした。作品ページの連携の候補も同じ部品
- **件数のバッジの読み上げ用の文字(`.sr-only`)はバッジの中に留める(`.count-badge` を `position: relative`)。** 外に出ると横に流れるタブの列の外にはみ出し、
  375px で開いたタブを `scrollIntoView` で送るとき画面ごと横に 58px ずれた(visual viewport が動く。`scrollWidth` では検出できない)

## 画面構成(#85。Peach との対応)

利用者の求めで、Peach(動画向けのローカルメディア管理アプリ)と同じく「常に表示するサイドバー + 管理のタブ」にした。

| Peach | SpineBox |
| --- | --- |
| メディアライブラリの切り替え(すべてのメディアライブラリ) | 蔵書の切り替え(すべての蔵書 / 蔵書ルートごと。`GET /api/libraries`) |
| ホーム・JAV・出演者・タグ・レーベル | ホーム(作品一覧)・漫画・小説(`#/manga` `#/novels`。種別で絞った作品一覧)・著者・タグ・出版社(値の一覧 → その値の作品一覧) |
| フォロー・ブックマーク | フォロー(`#/follows`。#87)・ブックマーク(`#/bookmarks`。#86)。どちらも単独の画面をそのままサイドバーの中に出す |
| 管理: 統計・好み・データ管理・統合・フォロー管理・タスクセンター | 統計・好み・スキャンと補完・整理・フォロー管理・タスクセンター(`#/admin`・`#/admin/<tab>`。tab は `preferences` / `data` / `organize` / `follows` / `tasks`)。統合の提案は確認へ移し、整理はデータ管理から独立させた(#207) |
| (無し) | 確認(`#/review/<tab>`。#207)。サイドバーの管理の上に件数のバッジつきで置く |
| 下: ライト/ダーク・テーマ・設定 | 下: ライト/ダーク・設定(= 管理の好みタブ)。パレットの切り替えは無い |

- **既存の画面はサイドバーの中に収め、どのナビの下かを `activeNav()` で決める。** 作品ページ・巻の一覧はホーム、統合の提案・重複の候補は確認、受け入れ・整理は管理。
  リーダーだけはサイドバーを出さない(読むときに画面を狭めない)。直リンク `#/read/<id>` もそのまま
- **横長では常に表示し、開閉ボタンでアイコンだけの帯(60px)にする。スマホ幅(CSS の 768px 未満)ではハンバーガーの引き出し。**
  幅の判定は CSS だけで行い、JS は「細くしたか(`spinebox.sidebar`)」と「引き出しが開いているか」だけを持つ(回転で幅が変わっても状態が食い違わない)。
  引き出しはナビを選ぶ・画面が変わる・Esc・背景のタップで閉じる
- **ライト/ダークは CSS 変数の 2 組。** `<html data-theme>` があればそちら、無ければ `prefers-color-scheme` に従う。既定は OS に従い、
  サイドバーの切り替えを押すと「いま効いている方の逆」を `localStorage`(`spinebox.theme`)に記憶する。OS に従うへ戻すのは好みタブから。
  `main.tsx` で描画の前に適用するのは、ダークで開いたときに一瞬ライトになるのと、リーダーから直接開いたときに付かないのを避けるため

## 落とし穴

- モック(`src/mock/`)は `vite.config.ts` からだけ読む。アプリ側から import すると本番のバンドルに入る
- 単体テストの jsdom には `PointerEvent` が無いので、小説のタップ・スワイプは判定関数の単体テストと実ブラウザで確かめる
- 漫画のリーダーのテストはライブラリをモックする(本物は jsdom の `matchMedia` が無くて組めない。[[manga-reader]])
- CSS で `.page` のような汎用のクラス名に紙面用のスタイル(`pointer-events: none` など)を付けない(#99)。画面共通のコンテナ枠 `<div className="page admin">` と衝突して、
  画面全体のタブやリンクがクリックできなくなった。jsdom は CSS のポインターイベントを解釈しないため単体テストでは見逃されやすい

## CI への組み込み

`scripts/ci_local.py:37 frontend_commands()` が `test` ジョブの最後に `npm --prefix frontend test` を足す([[local-ci]])。

- `frontend/package.json` が無ければ足さない。`node_modules` が無ければ**飛ばさずに** `npm ci` から始める
  (飛ばすと検査していないのに成功が載る)
- npm は Windows では `npm.cmd` なので、`shutil.which()` で解決したパスで呼ぶ(名前のままだと `subprocess` が見つけられない)
- Actions(`.github/workflows/test.yml`)は先に `npm ci --prefix frontend` を実行するので、スクリプト側の `npm ci` は走らない
