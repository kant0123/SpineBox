# フロントエンド(`frontend/`)

蔵書一覧と、右綴じ・見開きのリーダー。React + Vite + TypeScript。`npm run build` の出力 `frontend/dist` を
バックエンドが `/` で配信する。

## 責務

- する: 一覧(`GET /api/volumes`)・スキャンの起動(`POST /api/scan`)・巻の食い違いのバッジと説明・「中の巻を調べる」(`POST /api/volumes/{id}/analyze`)・重複候補の画面と一覧の印([[duplicate-detection]])・作品の一覧 / 作品ページ / 統合の提案の画面([[work-grouping]])・リーダー(ページ画像の表示・先読み・
  読書位置の保存と再開)・整理(CBZ 化)のプレビュー → 実行と、履歴からの元に戻す・範囲指定の整理(テンプレートの入力・パラメーターのチップ・パスの例・プレビュー → 実行 → まとめて元に戻す)([[organize]])。表示設定(見開き・表紙単独)は端末ごとに `localStorage` へ
- しない: ページの並び順・ページ数・オフライン判定・巻番号と食い違いの判定。どれもバックエンドが決めた `pages[]`・`offline`・`findings` をそのまま使う

## 決めたこと(コードからは理由が読めないもの)

- **ページ番号は 0 始まり。** `progress.page` も `pages[].index` と同じ番号で送る(画面の表示だけ +1)。
  #14 と同時に作ったため、契約の文面に始まりの番号が無かった。バックエンドと食い違ったら API 契約側を正にして合わせる
- **位置は「画面」ではなく「ページ」で持つ。** 回転や表紙単独の切替で見開きの組み方が変わっても、読んでいたページを
  含む画面から再開できる(`spreadIndexOf()` で範囲外のページも端に寄せるので、ページ数が減った巻も開ける)
- **見開きは表紙単独 ON が既定。** ON なら `[0] [1,2] [3,4] …`、OFF なら `[0,1] [2,3] …`。端数の 1 ページは最後に単独。
  DOM 上は若い番号が先で、CSS の `flex-direction: row-reverse` で右に置く(右綴じ)。見開きにするのは横長かつ幅 600px 以上のときだけ
- **操作の向き(右綴じ):** 左 1/3 タップ・`←` キーが次、右 1/3・`→` が前、中央がメニュー。スワイプは**右へ払う(指を左から右へ)と次**。
  Issue #15 の文面は「左スワイプ = 次」だったが、右綴じでは次のページが左から来るので、それを引き寄せる向きにした。
  逆が良ければ `swipeAction()` の符号だけを変える
- **一度既読になった巻は、前のページへ戻っても `finished=true` のまま送る。** 読み返しで既読が消えないようにするため
- **保存は 800ms のデバウンスで最後の位置だけ。** 一覧へ戻る・タブが裏に回る(`pagehide`/`visibilitychange`)ときは待たずに
  `fetch(..., {keepalive: true})` で送る。スマホはタブを閉じずに切り替えることが多く、デバウンス中の位置が失われるため
- **画面の切り替えはハッシュ(`#/read/<id>`)。** バックエンドは `dist` を `/` で配信するだけでよく、深いパスを
  `index.html` へ振り向ける設定が要らない。ルーターのライブラリも入れていない。
  ただし共有されたリンクやブックマークが `/read/<id>`(パス)の形だと、バックエンドの SPA fallback で画面は開くがハッシュが空で一覧になる。
  そのため起動時に `frontend/src/route.ts:73 canonicalUrl()` が `/#/read/<id>` へ `replaceState` で直す(#19)
- **食い違いの説明はカードのリンクの外の `<details>` に置く。** リンクの中に置くと、説明を開くつもりのタップでリーダーへ飛ぶ。
  バッジ(「巻の食い違い」)はリンクの中。分解で作った子の巻には「「親の名前」の中」と出す。同じ食い違いは親の子すべてに出る([[volume-split]])
- **整理は一覧のカードの「CBZ に整理」から。** 押しただけでは計画(プレビュー)を作るだけで、蔵書は動かない。
  実行ボタンは計画が `planned` のときだけ出す(`blocked` は理由だけ出す)。サーバーの 409 の `detail` をそのまま見せる。
  プレビュー画面を確認の代わりにして、`window.confirm` は使っていない
  中の巻をまだ調べていない内側アーカイブを含むソースは `blocked` になり、「中の巻を調べて計画を作り直す」だけを出す(調べるのは明示操作で、プレビュー自体は解析しない。[[organize]])
- **テンプレートどおりの整理は作品ページの「この作品をテンプレートどおりに整理」から。** 全巻を変更前 → 変更後と
  改名・移動 / そのまま / 対象外 / 衝突 / 外した、の札と理由で並べる。衝突の巻の「この巻を外す」は計画を作り直すだけ
  (外した巻のリストを送り直す)。1 巻 = 1 CBZ でない巻には「テンプレートの名前で CBZ に整理」へのリンクを出す。
  これらの操作はプレビュー中だけ出し、履歴では出さない
- **スキャンの結果は「N 巻を検出」と「読めなかったもの N 件」(開くと理由の一覧)を出す(#48)。** 件数が 0 なら出さない。
  サーバーの `issues` は最大 200 件なので、切った分は「ほか N 件は省略しました」と知らせる。スキャンが失敗したら、サーバーの `detail`
  (型とメッセージ)をそのままエラー表示に出す。固定の文言だけだと、サーバー機で何が起きたか画面から分からなかった
- **作品カードに表紙を出す(#75。[[cover-thumbnails]])。** `cover_volume_id` の巻の縮小画像を `<img loading="lazy">` で取り、
  読み込めたら見せ、404(入れ子の巻でまだ作っていない・小説・1 ページ目が画像でない)なら要素ごと消して文字だけのカードのまま。
  読み込み中は枠だけ(透明)で、消えたときだけカードの高さが変わる。入れ子の巻の表紙は「表紙を作る」(明示操作)で作り、終わったら `?rev=` を変えて取り直す。
  巻の一覧のカードには出していない(要望は作品の一覧。同じ `api.thumbnailUrl()` で足せる)
- **読み込み待ちは 2 段で見せる(#26)。** 入れ子のアーカイブ(7z の中の rar)を初めて開くと、`GET /api/volumes/{id}` が内側を
  取り出す間(実測 3〜8 秒)何も出ず、黒い画面のままで読み込み中と分からなかった。巻情報の取得中はリーダーの黒い枠の中央に
  スピナーと「一覧へ戻る」を出し、1.5 秒(`SLOW_HINT_MS`)を超えたら「初めて開く巻は展開に数秒かかる」と補足する。
  巻情報が来た後は、表示中のページ画像が `load` / `error` になるまで画面中央に小さく「読み込み中」を重ねる。
  先読み済みのページで一瞬ちらつかないよう、重ね表示は CSS で 0.3 秒遅れて現れる
- **先読みで読み終わっていた画像は、表示ページが変わったときに `useLayoutEffect` で一度だけ調べる(#51)。** 描画前に
  読み終わった画像には `load` が来ないので、`complete && naturalWidth > 0` を見て読み込み済みにする。当初(#26)は `<img>` の
  インラインの `ref` コールバックの中でこれを行い `setLoaded` していたが、実ブラウザでは見開きで 2 回目のページ送り(次の見開きが
  先読み済みで complete)から更新が繰り返され、React #185(Maximum update depth exceeded)で描画が止まって真っ黒になった。
  **ref コールバックの中で state を更新しない**(描画のたびに付け直される)。jsdom ではこのループは再現しなかったので、
  確認は実ブラウザで見開き・単ページとも数十ページ送って行った
- **取得失敗の文言は HTTP ステータスで分ける。** 404 は「蔵書から無くなった」、409 は「オフライン」、422(壊れたアーカイブ・
  展開上限超過)はバックエンドの `detail` をそのまま出す。理由はバックエンドしか知らないため。どの失敗でも一覧へ戻るリンクを出す
- **重複候補の画面は何も消さない。** 見比べて「重複ではない」を付けるだけで、削除・移動のボタンは置かない(重複の解消は CBZ 化の整理の役目)。2 巻の表紙は 1 ページ目の画像(`api.pageUrl(id, 0)`)で、
  別スキャンは 1 ページ目が口絵と表紙で食い違うことがあるので、バックエンドが返す一致ページの例(最大 3 組)も並べる。375px では 2 巻を 2 列のまま、項目名を値の上に積む
- **一覧の印「重複の候補あり」は巻のリンクの外**(食い違いの説明と同じ理由)。押すと重複候補の画面へ行く
- **汎用カルーセルライブラリは使わない**(GOAL.md の初期既定)。ページ送りは状態の差し替えだけで、アニメーションは無い
- **小説は同じ `#/read/<id>` で開き、巻情報の `format` でリーダーを切り替える。** 一覧のカードには「小説」の印と「EPUB / テキスト」を出し、
  ページ数・「CBZ に整理」は出さない。読みかけは「読みかけ(区切り / 区切りの数)」(ページ数は文字サイズで変わるので出さない)。
  文字サイズは端末ごとに `localStorage` の `spinebox.novel` へ([[novel-reader]])

- **作品ページの「手で直した項目」は出所を明示する。** 作品名・著者・別名・巻の割り当てごとに「手動で編集 / ファイル名から(確信度 90%)/ 重複候補の証拠で統合」を出す。名寄せは名前の推測なので、利用者が根拠を見て直せるようにするため。
  提案は確信度と根拠(一致ページ数)を見せ、承認するまで統合しない。巻の付け替えは巻のチェックボックスで選んで「新しい作品に分ける」/「この作品へ移す」(手動の決定になり再計算で戻らない)
- **ジャンル・タグ・出版社・候補はサーバーが日本語にして返すので、画面では訳さない**(#74)。あらすじは #82 で廃止し、作品ページに表示・編集の欄を置かない([[metadata-linking]] の「あらすじの廃止」)
- **作品一覧の検索と絞り込みは、スマホ幅で 1 行に収める。** 検索欄と「絞り込み」ボタンの 1 行だけを常に出し、読書状態・著者・種別・ジャンル・タグの選択はボタンで開いたときだけ出す(開いていなくても選んだ数をボタンに出す)。候補の無い項目(公開 DB の情報がまだ無い作品だけのときの種別・ジャンル・タグ)は選択欄ごと出さない。種別の候補は `manga` / `novel` で届くので `KIND_TEXT` で漫画・小説と表示する。検索語は打鍵ごとに引かず 250ms 待ってから引き(`SEARCH_DELAY_MS`)、後から出した要求の結果を古い応答で上書きしない。絞っているときは「N 件 / 全 M 作品」と「条件を消す」、0 件なら「条件に合う作品がありません」(蔵書が空のときの文言と分ける)。モック API の検索は `frontend/src/mock/mockWorks.ts:22 normalizeSearch()` でバックエンドと同じ正規化を真似ている
- **公開 DB の値は項目ごとに出所を出す。** 「公開データベース: 国立国会図書館サーチ(確信度 100%)」「手動で編集」など。確認待ちの候補は「これを採用」を押すまで反映しない(候補は種別・出版社・巻数・一致度つきで、同じ名前の漫画と小説を見分けられるように採用ボタンの名前にも種別を入れる)。
  取得元が落ちているときは理由を出し「すでに入っている値はそのまま」と添える。NDL の候補を選んで種別が決まったら、保留だった取得元を保存済みの応答で連携し直す(通信は出ない)。国立国会図書館サーチの利用明示のため、作品の一覧と作品ページの末尾に利用元を出す([[metadata-sources]])
- **作品の一覧と巻の一覧は別画面で、既定は巻の一覧のまま。** 作品の画面は `#/works`。巻の一覧のカード・リーダーは変えていない

## 落とし穴

- `.stage` の `touch-action: pinch-zoom` は、1 本指の横の払いをブラウザのスクロールに取られないためのもの。消すとスマホでスワイプが効かない
- モック(`src/mock/`)は `vite.config.ts` からだけ読む。アプリ側から import すると本番のバンドルに入る
- jsdom の画像は読み込まれず `load` も来ないので、ページ画像の読み込み待ちのテストは `fireEvent.load` / `fireEvent.error` で進める
  (`src/reader/Reader.test.tsx`)。先読み済み(complete)の画像の分岐は `HTMLImageElement.prototype` の `complete` / `naturalWidth` を差し替えて通す
- 単体テストの jsdom には `PointerEvent` が無いので、タップ・スワイプは判定関数の単体テストと実ブラウザで確かめる
  (結線のテスト `src/App.test.tsx` はキーボードで操作している)

## CI への組み込み

`scripts/ci_local.py:37 frontend_commands()` が `test` ジョブの最後に `npm --prefix frontend test` を足す([[local-ci]])。

- `frontend/package.json` が無ければ足さない。`node_modules` が無ければ**飛ばさずに** `npm ci` から始める
  (飛ばすと検査していないのに成功が載る)
- npm は Windows では `npm.cmd` なので、`shutil.which()` で解決したパスで呼ぶ(名前のままだと `subprocess` が見つけられない)
- Actions(`.github/workflows/test.yml`)は先に `npm ci --prefix frontend` を実行するので、スクリプト側の `npm ci` は走らない

## 経緯

- #75 で作品カードに表紙と「表紙を作る」を足した([[cover-thumbnails]])。モック API は入れ子の巻(`page_count` 未確定)の表紙を、開くか作るまで 404 pending にする。
  `npm run dev:mock` を 375px と 1000px のヘッドレス Chromium で開き、作成前は入れ子の作品が文字だけのカード・作成後に表紙が出ること、横スクロールとコンソールのエラーが無いことを確認した。
