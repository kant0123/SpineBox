# アーカイブの読み取り

アーカイブを解凍せずに目次を読み、1 エントリをメモリ(または呼び出し側が渡したファイル)へ読み出す層。
エントリ名をディスク上のパスに使わない。

## 責務

- する: 目次の列挙、名前の復号(生バイト列と使った文字コードを残す)、危険な名前のスキップ、展開上限の判定、1 エントリの読み出し
- しない: どれを巻にするかの判断([[backend]] のスキャナー)、ディスクへの展開(内側アーカイブの取り出し先は [[extraction-cache]])

## 入口となるファイル

| パス | 役割 |
| --- | --- |
| `spinebox/archive/base.py:94 list_entries` | 形式によらない検証(名前・上限)。リーダーを使うときは必ずここを通す |
| `spinebox/archive/base.py:139 open_archive` | 拡張子でリーダーを選ぶ。`reader_available()` は 7z / rar を「7-Zip が見つかるとき」だけ true にする |
| `spinebox/archive/sevenzip.py:200 SevenZipReader` | 7z / rar / cb7 / cbr。目次は `parse_listing()`、取り出しは `_stream()` |
| `spinebox/archive/zipreader.py:54 decode_name` | zip の名前の復号順 |

| `spinebox/pages.py:48 page_sort_key` | ページの並び(表紙 → 自然順) |

## 名前の復号

実データの zip には UTF-8 フラグあり・Unicode Path 拡張つき・cp932 が混在する(GOAL.md「試作で確かめた前提」)。

1. 汎用ビット 11(UTF-8 フラグ)→ UTF-8
2. Info-ZIP Unicode Path 拡張(0x7075)で、CRC がヘッダの生の名前と一致する → その UTF-8 名。
   CRC が合わないのは「名前だけ別ツールで書き換えられた」印なので使わない
3. ASCII だけなら `ascii`、そうでなければ cp932、駄目なら cp932 の置換文字入り(`cp932 (replaced)`)

生バイト列は `ZipInfo.orig_filename` から復元する(zipfile はフラグが無ければ cp437 で読むので、cp437 で符号化し直せば
元の 256 値に戻る)。**zipfile 自身の 0x7075 解釈(`filename` の書き換え)は使わない。** 3.12 と 3.13 で
名前の扱いが違い、壊れた 0x7075 で `BadZipFile` を投げる版もあるため、自前で解釈して版に依存しないようにした。
cp932 の 2 バイト目には `0x5C`(`\`)が来る(例: 「ソ」)ので、区切りの判定は復号後の文字列で行う。

UTF-8 フラグ無しで UTF-8 の名前(macOS の標準機能で作った zip など)は、今の順だと cp932 として化けうる。
Issue #14 の指定順に従っている。実データで出たら順の見直しを検討する。

## 7z / rar(7-Zip CLI)

`sevenzip_path`(設定。名前だけなら PATH、パスならそのファイル)の `7z.exe` を子プロセスで呼ぶ。
目次は `7z l -slt -ba`、1 エントリは `7z e -so`(標準出力に流すだけで、ディスクに展開しない・元の階層も作らない)。

- **見つからないときは UnsupportedArchive(「未対応」)。** zip / cbz は 7-Zip なしで読める。スキャンは理由を記録して
  そのアーカイブを一覧から外し(サイズ・mtime は記録しないので、設定を直して再スキャンすれば拾う)、内側の 7z / rar は取り出す前に 422
- **出力は信用しすぎない。** `-sccUTF-8` で文字コードを固定し、CRLF・BOM・`----------` より前の前置きを読み飛ばす。
  `splitlines()` は名前の U+2028 等で割れるので使わず改行文字だけで分ける。空出力・解釈できない出力・非ゼロ終了・タイムアウト
  (目次 300 秒、取り出し 1800 秒)・サイズ欠落は、空のアーカイブ扱いにせず `ArchiveError`(= 巻としては 422)
- **ワイルドカード解釈は `-spd` で止め、引数は `--` の後ろに置く。** 名前の `*` `?` で別エントリに誤爆したり、`-` や `@` 始まりの名前が
  スイッチ・リストファイル扱いされたりしない。取り出しに渡す名前は 7z が目次に出したままの文字列(Windows では `\` 区切り)で、
  検証済みの名前(`list_entries` を通ったもの)だけを渡す
- **取り出したバイト数が目次のサイズと違えば `ArchiveError`。** 同名エントリが複数ある・壊れているときに、別の中身を返さない
- フォルダ名は 7z だと末尾に区切りが付かないので、zip と同じく末尾 `/` を付けて返す(スキャナーが巻のフォルダ名の生バイト列を引くため)
- シンボリックリンクは目次から落とす(画像として読まない)。暗号化はパスワードを聞かれて失敗するので `ArchiveError`
- **ソリッド圧縮は 1 ページずつ取り出すと毎回先頭から展開する。** そのため外側の 7z からは内側アーカイブだけを取り出して
  [[extraction-cache]] に置き、ページはそこから読む。内側の rar がソリッドだとページごとに展開し直すが、実データ(非ソリッド)では
  1 ページ数十 ms だった
- 実データ(`_参考/サンプル本`)の形: 7z の中に rar があり、その中に rar と zip があり、さらに zip がある(深さ 3)。
  内側にさらにアーカイブがあれば、深さの上限(`max_depth` 既定 3)まで開いて、各段の画像 → 入れ子の順で続ける。
  開いたときに中の巻の単位を集めて子の巻に分ける([[volume-split]])。`max_depth` を変えると見える単位が変わるので、解析し直す
  重複候補のための指紋(全ページの縮小デコード)も、この経路で巻を開いて 1 ページずつ読む([[duplicate-detection]])

## 危険なエントリ名と展開上限

- 拒否: `..` を含む・絶対パス(`/` `\`)・ドライブ文字(`C:`)・UNC(`\\server`)・NUL・空。目次の段階でスキップし、
  `scan_issues`(内側アーカイブなら `container_path` 付き)に理由を残す。安全な名前も区切りを `/` に正規化するだけで、パスには使わない
- 上限(`[limits]`): 1 アーカイブのエントリ数・展開後サイズの合計(目次の宣言値)・1 エントリの展開サイズ・入れ子の深さ。
  アーカイブ全体の上限超えは `LimitExceeded` でアーカイブごとスキップ。1 エントリは読み出し時に宣言値と実際の書き出し量の両方で判定する
- 合計サイズの既定を 64 GiB と大きめにしているのは、全巻を 1 つにまとめた外側アーカイブが実在するため。
  目次の宣言値を見るだけでスキャンでは展開しないので、ここは壊れた・異常なヘッダを弾く役
- 入れ子の深さは「外側の中の内側」を 1 と数える。既定 3(実データが 7z → rar → rar → zip)。超えた入れ子は開かず `scan_issues` に残す
  (スキャンの巻の切り出しは深さ 1 だけ。深さの上限を絞っても一覧の件数は変わらず、開いたときに先が読めなくなる)

## 落とし穴

- リーダーの `raw_entries()` を直接使わない。名前の検証と上限判定が `list_entries()` にしか無い
- テストで cp932 名(フラグ無し)の zip を作るとき、`zipfile` の書き込みは版で挙動が違う(3.12 は非 ASCII を常に UTF-8 + フラグ、
  3.13 はフラグ無しなら cp437 で符号化)。`tests/conftest.py:21 RawName` で生バイト列を直接書く
- 暗号化エントリ・未対応の圧縮方式は読み出し時に `ArchiveError` になる(巻としては 422)。暗号化 zip は目次が読めるので、スキャンでは巻として登録され、開いたときに 422
- zip は同名のエントリを複数持てる。スキャンは同名の内側アーカイブを最初の 1 つだけ巻にして、残りを `scan_issues` に残す([[backend]])
