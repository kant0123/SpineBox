# メタデータの取得元(公開 DB)の癖と制限

GOAL.md「メタデータの取得元」の方針(国立国会図書館サーチが巻ごとの書誌の主力、作品単位のタグ・全巻数は他の取得元、楽天ブックスは今は使わない)を
#44 で実装するときに、実通信(2026-11-02)と公開ドキュメントで確かめたこと。クライアントの構造は [[metadata-clients]]。
**取得元の仕様は予告なく変わる**ので、ここの数字は「いつ確かめたか」込みで読む。食い違いを見つけたらコードの挙動が正でここを直す。

**AniList・MangaUpdates は #278(2026-11-10)でメディア芸術データベース・Bangumi に置き換えた**(クライアントのコードも削除済み、採否の理由は「使わない・後回しの取得元」の表)。
AniList はレート制限が障害対応で 30 回/分に下がっており(当時)、保存の永続化も利用条件で禁じていた。MangaUpdates は
レート制限が文書化されていなかった。置き換え後の 2 つはどちらもキー不要で、応答も速い(メディア芸術データベースは
Neptune の全文検索を使うと 0.2〜0.3 秒、Bangumi は 0.3〜0.6 秒)。

## 国立国会図書館サーチ API(`ndl`)— 巻ごとの書誌

| 項目 | 内容 |
| --- | --- |
| 使うもの | OpenSearch `https://ndlsearch.ndl.go.jp/api/opensearch`(RSS 2.0 の拡張)。`title` / `creator` / `isbn` / `mediatype=books` / `cnt`(上限 500、501 件目以降は取れない) |
| キー・料金 | 不要。**非営利で対価を得ないなら申請不要**(広告収入・対価があれば申請)。継続的に使うなら API 利用申請フォームでの連絡が求められている(承認は不要)。**このアプリは個人・非営利の利用なので、継続利用の申請はしない(2026-11-02 利用者判断、#45)**。広告・対価を伴う使い方に変えるときは判断し直す |
| 表示義務 | アプリ・サイトは NDL サーチ API を利用していることを明示する。**実装済み(#50)**: 作品の一覧と作品ページの末尾に、有効な取得元の名前・サイトへのリンク・「NDL サーチ API」などの API 名を出す(`frontend/src/works/Credits.tsx:6 Credits()`)。候補・連携済みの項目には出典 URL のリンクがある |
| 制限 | 数値は公開されていない。**同時リクエスト数に制限**があり、高負荷が続くとサーバーごと遮断されうる。並列に送らない |
| 既定の間隔 | 1.0 秒(直列。数値の根拠は無く、同時要求を避けて人が検索する速さに収めた値) |
| 応答 | UTF-8、`text/xml`。1 件 ≒ 3 KB |

**SRU(`/api/sru`、`recordSchema=dcndl`)でなく OpenSearch にした理由。** 同じ作品名で両方を引いて比べた。OpenSearch の `item` は巻次(`dcndl:volume`)・シリーズ名(`dcndl:seriesTitle`)・
出版者・発行年月(`dcterms:issued`)・ISBN・著者(姓, 名)と読み・ジャンル(`dcndl:genre` = 漫画)・NDC を既に持つ。SRU の dcndl は 1 件が約 14 KB の RDF/XML で、
増えるのは別タイトル(パラレルタイトル = 英題)と所蔵情報(`dcndl:Item`、使わない)程度。パース・転送量・実装の分かりやすさで OpenSearch を採った。
英題が要るようになったら SRU の `dcndl:alternative` を足す手がある(AniList / MangaUpdates からも別名は取れるので今は要らない)。

癖:

- **同じ作品名で漫画版と小説版が別の巻として混ざって返る**(「お気楽領主の楽しい領地防衛」は ガルドコミックス版 と OVERLAP NOVELS 版)。`kind` はジャンル・NDC(726.1 漫画 / 913 小説)・シリーズ名から推す。
  判断できなければ None(決めつけない)
- **作品名だけで引くと別の本が大量に混ざる**(「かくかくしかじか」は詩集・CD ブック・映画ノベライズが先頭)。`creator` を付けると東村アキコの 1〜5 巻だけに絞れる(表記は `東村アキコ` でも `東村 アキコ` でも可)。
  クライアントは著者があれば `creator` で引き、**0 件なら著者なしで引き直す**(著者の表記が NDL と合わない場合のため)
- 著者は `東村, アキコ, 1975-` のように**生没年が付く**ことがある。`赤池, 宗` は姓名の連結に直す(欧文は `John Smith`)
- 巻次は文字列(`1` `上` `1-2`)。数字だけのとき `volume` に数値を入れ、元の表記は `volume_label` に残す
- 作品名は `作品名 : 副題`。主題と副題を分けて持つ(題名の比較は主題で行う)
- **ローマ字の検索語でも日本語の項目が当たる**(読みで引いているらしい)。項目の読み(カタカナ)をローマ字にして題名と比べるため、確からしさは出せる(`spinebox/metadata/kana.py:40 to_romaji`)
- **内容紹介(あらすじ)は無い。** `dc:description` は「奥付のタイトル: …」「出版」「展覧会カタログ」のような書誌の注記と年で、あらすじではない(記録済みの 4 検索で確認、#74)。日本語のあらすじの取得元にはならない
- `dc:date` / `dcterms:issued` は発行の年月。RSS の `pubDate` は書誌レコードの更新日で、発売日ではない(使わない)

## メディア芸術データベース(`mediaarts`)— 作品単位の全巻数・著者・出版社

| 項目 | 内容 |
| --- | --- |
| 使うもの | SPARQL `GET https://mediaarts-db.artmuseums.go.jp/sparql`。`class:MangaBookSeries`(シリーズの実体)と `class:MangaBook`(巻)を Neptune の全文検索(`SERVICE neptune-fts:search`、`rdfs:label` 対象)で絞り、`FILTER(CONTAINS(...))` で読みなどの誤爆を削る |
| キー・料金 | 不要。CC BY(表示義務は NDL と同様に検討。#278 の時点では未実装) |
| 制限 | 公式の数値は見当たらず(未確認)。既定の間隔は NDL と同じ控えめな値にした |
| 既定の間隔 | 1.0 秒(未検証につき NDL と同じ値) |

**旧ドメイン `https://mediaarts-db.bunka.go.jp/sparql` は証明書が切れて接続不可**(2026-11-10 に確認。ドメイン移転したとみられる)。新ドメイン `mediaarts-db.artmuseums.go.jp` を使う。
Neptune の全文検索を使わない `rdfs:label` の全件 `CONTAINS` スキャンは 1 クエリ 3.6 秒かかった(実測)。全文検索を併用すると 0.2〜0.3 秒。

癖:

- **シリーズの実体(`class:MangaBookSeries`)は全作品に登録されているわけではない**(実通信で確認。「お気楽領主の楽しい領地防衛」にはシリーズの実体が無く、巻だけ登録されていた)。
  シリーズの実体があれば `schema:numberOfItems`(確定の全巻数)を使い、無ければ検索で見つかった巻の `schema:volumeNumber` の最大値を全巻数の下限として使う(大作では全文検索の件数上限に収まらず過少になりうる)
- **対象は漫画のみ**(小説・アニメ・ゲームは別クラスで検索しない)。`kind` は常に `manga`
- 巻・シリーズの `schema:name` には読み(`ja-hrkt`、カタカナ)つきの値も入っている。作品名の候補からは除くが(除かないと読みの違いだけの別候補が二重に出る)、
  `MetadataItem.reading` には入れる。NDL と同じ経路(読みをローマ字にして比べる)で、ローマ字のファイル名の蔵書でも一致させるため
- ジャンル・タグの構造化された語彙は持たない(NDC の分類はあるが、少年・青年のような区分ではない)。`MetadataItem.genres` / `.tags` は常に空
- 実データにノイズが混ざる(「お気楽領主の楽しい領地防衛」の検索で `schema:name` が `Fu` だけの無関係な巻が混ざった)。確からしさで下位になり、閾値未満なら自動連携に影響しない

## Bangumi(`bangumi`)— 作品単位の全巻数・著者・出版社

| 項目 | 内容 |
| --- | --- |
| 使うもの | 検索は巻ごとに別項目になる旧 API `GET https://api.bgm.tv/search/subject/{keyword}?type=1`(部分一致)。著者・出版社は上位の候補だけ新 API `GET /v0/subjects/{id}` で詳細を引く |
| キー・料金 | 不要 |
| 制限 | 公式の数値は見当たらず(未確認)。既定の間隔は NDL と同じ控えめな値にした |
| 既定の間隔 | 1.0 秒(未検証につき NDL と同じ値) |

癖:

- **巻ごとに別項目で返る**(`かくかくしかじか (1)` 〜 `(5)`)ので、巻次の接尾辞(`(N)`)と、どの巻にも付く定型のサブタイトル(`~…~`)を外して同じ作品名にまとめる
  (`spinebox/metadata/bangumi.py _base_name()`)。番号の付かない項目(作品の代表の項目)があればそれを詳細の対象にする
- **巻次でまとめる都合上、同じ作品名の漫画版と原作小説版が 1 件に混ざることがある**(実データで、全巻数が実際の漫画の巻数より多く出た)。
  NDL のように種別で割れて返るわけではないので、`kind` は詳細(`platform`)を引いた候補にだけ付く
- 著者は詳細の infobox の「作者」キーに入るが、**作画・原作が分かれる作品は「作画」「原作」に分かれて入る**(実データで確認。両方を拾って結合する)
- **タグ(簡体字中国語)は読み取らない。** `spinebox.ja_terms.is_japanese()` は仮名の有無で日本語を見分けるため、仮名を含まない簡体字中国語の文を
  (漢字の字形が重なるので)日本語と誤認し、対応表に無い語を隠す既定の挙動が効かない(実データで確認。#284 に切り出した)
- あらすじは日本語で取れるが読み取らない(#82 の方針を踏襲)

## nHentai(`nhentai`)と E-Hentai(`ehentai`)— 同人誌(#275)

同人誌のファイル名の書式 `(イベント) [サークル (作者)] 題名 (原作) [印]` は、両サイトの題名と同じ書式なので、
**題名の核・サークル・作者で突き合わせて判定する**(`spinebox/metadata/doujin.py:48 parse_doujin_title()` が両側を同じ規則で読む)。
どちらも**既定では無効**(`[metadata] sources` に足すか、管理の「蔵書」タブでその蔵書の取得元に選んだときだけ使う。#316)。成人向けのサイトへ蔵書の作品名を送ることになるので、利用者の明示的な選択にした。
実通信(2026-11-10、`scripts/metadata_probe.py --source nhentai --source ehentai`)で、実際の蔵書の `(C70) [バルバロッサ (東雲太郎)] Flowers (ストリートファイター)` を
どちらも確からしさ 1.00(題名・著者・種別が一致)で特定できた。

| 項目 | nHentai | E-Hentai |
| --- | --- | --- |
| 使うもの | 公式 API v2。検索 `GET /api/v2/search?query=`、詳細 `GET /api/v2/galleries/{id}` | 公式 API は詳細の `POST https://api.e-hentai.org/api.php`(`gdata`)だけ。**検索 API は無い** |
| 仕様の入手 | ドキュメントページ(`/api/v2/docs`)は Swagger UI で JS 描画のため本文が取れない。**`/api/v2/openapi.json` を読む** | https://ehwiki.org/wiki/API |
| キー・料金 | 不要。キーは任意(`[metadata.keys] nhentai_api_key` → `Authorization: Key …`)。キーは要求の鍵・保存する記述・ログに出さない | 不要 |
| 制限 | 匿名は**検索 10 回/分・詳細 20 回/分**(IP ごと)、キーありは 20・45 回/分(公式の記述)。**既定の間隔 6.5 秒**(10 回/分 = 6 秒に余裕を足した値。キーを使うなら設定で 3.0 まで下げてよい) | 数値は無く「4〜5 回連続したら 5 秒ほど待つ」程度。守らないと IP が一時的に遮断される。**既定の間隔 4.0 秒**。`gdata` は 1 要求 25 件まで |
| 検索の形 | 一覧の項目は題名・ページ数・`tag_ids` だけ(タグ名・分類は無い)。分類・タグ名は詳細にだけある → 同じ本をまとめたあと、確からしさの上位 `detail_limit` 件だけ詳細を引く | 検索ページ(`https://e-hentai.org/?f_search=`)の HTML から `/g/{gid}/{token}/` のリンクだけを拾い(表示モードの見た目には頼らない)、まとめて `gdata` に渡す。1 検索 = 2 要求 |
| 0 件・異常 | `result` が空の成功 | 0 件は本文の `No hits found`(成功した 0 件)。リンクも案内も無いページは `invalid_response`。**遮断の案内は `rate_limited` として失敗させ、`MAX_RATE_LIMIT_BLOCK` の間は要求を出さない**(`spinebox/metadata/ehentai.py:35 BannedError`) |

癖:

- **日本語の題名でも当たる**(両サイトとも)。検索語に `:`(名前空間 `artist:…`)・引用符・先頭の `-`(否定)・`$` などを入れると検索の構文として読まれるので空白にする(`spinebox/metadata/doujin.py:108 search_keywords()`)
- **短い・ありふれた作品名だけで引くと無関係な本が混ざる**(`Flowers` はタグ・作者名が `Flowers…` の別物が先頭に来た)。そのため**検索語に題名のサークル名を足して引き、0 件ならサークル名なしで引き直す**(`spinebox/metadata/doujin.py:115 search_queries()`)
- **同じ本が翻訳版・再アップロードで複数並ぶ。** 日本語の原本 → 翻訳でない → 古い ID の順に 1 件を残す(`dedupe_key()`。翻訳は題名末尾の印 `[中国翻訳]` `[英訳]` `=訳者=` と言語タグで見る)。残さないと首位が 1.0 で拮抗し、結線が自動で連携できない
- **開催イベントは照合に使っていない。** E-Hentai には同じ本が `(C70)` と `(C72)` の 2 件あり(再録・別アップロード)、ID の古い方を残すと実物の `(C70)` に合うが、イベントで選んだわけではない。イベントは `label` に残すだけ
- 題名の書式は慣習で、括弧の無い題名・題名の一部の括弧がある(`涼月ちゃんとホワイト(意味浅)鎮守府`)。**原作の括弧として割るのは、イベント・サークルを読めた題名の末尾の括弧だけ。** 読めなければ題名を割らない
- 実際の蔵書の同人誌 882 件の名前で、イベントを読めたのが 229 件、サークル・作者を読めたのが 719 件、原作を読めたのが 270 件。残りは番号だけのフォルダ名などで、書式が無い(`(C101) [海凪コウ]放課後裏垢女子` のように `]` の直後に空白が無い・`[サークル(作者)]` の括弧の前に空白が無い形も読める)
- 作者名(英語)・サークル(英語)は項目に入れない(日本語の題名の書式を優先し、日本語の題名が無いときだけ英語の題名の書式を使う)。アップロード日は発行日ではないので `released` にしない
- シェル(Git Bash の `curl`)から日本語の検索語を渡すと文字が壊れて 0 件になる。**API の確認は Python から送る**(取得元のせいではない)

項目の写し方: 題名の核 → 作品名、英語の核 → ローマ字名、`題名 (原作)` → 別名、`サークル (作者)` → 著者(ファイル名の書式のまま)、サークル → 出版社、イベント → `label`、
分類(`doujinshi`)→ ジャンル「同人誌」と種別 manga、原作 → タグ。内容タグは英語なので、対応表(`spinebox/ja_terms.py`)に無ければ既定(`hide`)で作品には入らない。
本番での実測(2026-11-10、260 作品の `work_links.attempted_at` の差): 検索 + 詳細 1 件で nHentai は 7 秒(関門の 6.5 秒がそのまま出る)、E-Hentai は検索 + `gdata` で 5 秒。
国立国会図書館サーチは成功しても 1 要求 約 6 秒で、260 回中 157 回が失敗した(429 が 59 回、その後の停止中の即時失敗が 93 回、タイムアウトが 6 回)。
全作品をまとめて取るときに要求を減らす規則は [[metadata-clients]] の「軽い検索」と [[metadata-linking]]。

利用条件: どちらも個人・非営利で使い、User-Agent に `SpineBox/0.1 (personal library manager; non-commercial)` を付ける(nHentai が求める「アプリ名/版 (連絡先)」の形)。

## 使わない・後回しの取得元

| 取得元 | 理由 |
| --- | --- |
| openBD | API v1 の提供終了が告知されている |
| 楽天ブックス | ジャンル(少年・青年)・発売日が取れるが、API キー(アプリケーション ID)が要る。今は使わず、**取得元を差し込める形**(`SOURCE_CLASSES` への登録、`[metadata.keys]`、`SourceRequest.secret_params`)だけ用意した |
| AniList | #278(2026-11-10)でメディア芸術データベース・Bangumi に置き換えた。レート制限が障害対応で 30 回/分に下がっており(当時)、保存の永続化も利用条件で禁じていた。GraphQL・ローマ字名(`title.romaji`)・英語のジャンル・タグは持っていた |
| MangaUpdates | #278 で置き換えた。レート制限が文書化されていなかった。ローマ字名・英語のジャンル・タグ(少年・青年などの区分含む)・原版元のローマ字名は持っていた(メディア芸術データベース・Bangumi はこれらを持たない。ジャンル・タグが要るなら ehentai / nhentai の英語のタグで代替するか、別の取得元を検討する) |
| Web 小説系 API | 使わない(GOAL.md) |

| 検索語 | 国立国会図書館サーチ | メディア芸術データベース | Bangumi |

## 覆すとしたら

- メディア芸術データベース・Bangumi の制限が文書化されたら、既定の間隔をそれに合わせる。429 を実際に受けた記録が出たらここに数字を残す
- NDL サーチが検索の頻度を数値で示したら、それに合わせる
- E-Hentai が API の制限を数値で示したら、既定の間隔(4.0 秒)をそれに合わせる。遮断を受けた記録が出たらここに残す
- nHentai は検索と詳細を同じ関門(6.5 秒)で直列にしている。制限は検索 10 回/分・詳細 20 回/分と別々に書かれているが、**別々に数えられるかは確かめていない**。E-Hentai も検索ページと `gdata`(別ホスト)を同じ 4.0 秒で空けている。確かめられたら関門を分けられる
- nHentai の検索が日本語の題名を引けなくなったら、`japanese_title` で照合する前提が崩れる(英語の題名の書式で引く)
- `spinebox.ja_terms.is_japanese()` が仮名の無い簡体字中国語を見分けられるようになったら(#284)、Bangumi のタグを読み取る選択肢ができる
