# 公開 DB の結線(`spinebox/linking.py`)

[[metadata-clients]] が返す候補を、作品(`works`)と巻(`volumes`)の項目へ結ぶ(GOAL.md フェーズ 3「公開データベースから埋まる」、#50)。
クライアントは候補と確からしさを返すだけで、**どれを採るか・どう埋めるかはここ**。取得元の癖は [[metadata-sources]]、作品・項目の持ち方は [[work-grouping]]。

## 全体像

```
fetch_work(作品, 取得元)  ← 唯一ネットワークに触る。データ管理のジョブ/作品ページの「情報を取得」/裏の定期取得からだけ
   │  候補を作って work_links に保存(自動で連携 / 確認待ち / 該当なし / 失敗の記録)
   ▼
apply_work(作品)          ← DB だけで完結・冪等。fetch・choose・reset・スキャン後に走る
   │  連携から work_fields / work_aliases / volume_fields を導出
   ▼
```

**スキャン・閲覧・編集はネットワークに触らない**(CLAUDE.md「取得失敗でスキャンと閲覧を止めない」)。`apply_work` は連携の中身(保存済み)の純関数なので、
スキャンで巻が増えれば `apply_all` が新しい巻へ書誌を入れ、連携を外せば公開 DB 由来の値だけが消える。

## 連携の決め方(`spinebox/linking.py:167 decide()`)

- 取得元ごとに 1 作品 1 行(`work_links`: `status` = `linked` / `pending` / `none`)。`manual` は利用者が選んだ連携
- **自動で連携するのは、最良候補の確からしさ ≥ 0.75 かつ 2 位との差 ≥ 0.15**(`AUTO_LINK_MIN` / `LINK_MARGIN`)。足りなければ `pending`(確認待ち)で、0.5 以上の候補を最大 5 件見せる。
  数値の根拠は実データ(`_参考/サンプル本` の 2 作品)で、かくかくしかじかは 1.0 対 0.71、お気楽領主は漫画 1.0 対小説 1.0 の同点。閾値の調整は `tests/test_linking.py` の同点・僅差のケースを見てから
- 作品の種別(`kind`)が分かっていれば、種別の違う候補は除く
- **名前の部分一致は、短い方の名前が長い方の先頭にあるときだけ強めに見る**(`spinebox/metadata/match.py:62 title_score()`)。
  副題・巻数が後ろに付く形(`作品名` と `作品名 生産系魔術で…`)は同じ作品の別表記とみなすが、末尾・途中にしか無い一致は
  似ている度だけで採点する。実データ(#158)では `57 files`(ファイル数の見出し)に MangaUpdates の別名 `FILES` が
  末尾で含まれるだけで 0.8143 になり、自動連携の基準(0.75)を超えていた
- **種別が決まっていない作品で国立国会図書館サーチが漫画と小説で割れているときは、AniList / MangaUpdates も確認待ちにする(`hold = "kind_unresolved"`、`kind_unresolved()`)。**
  お気楽領主は MangaUpdates の漫画が名前完全一致で差が付き、先に自動連携して種別と著者を書いてしまった(NDL の割れを無視した誤り)。NDL の候補を選ぶと、次の取得(保存済みの応答を使うので通信は出ない)で残りが自動で決まる
- 国立国会図書館サーチは 1 冊ずつの書誌なので、**(種別・作品名・シリーズ名・著者)が同じものを「組」にして連携の単位にする**(`_ndl_groups()`)。組の確からしさ = 最良の巻 × 0.85 + 手元の巻番号を組が覆う割合 × 0.15。
  同じ名前で巻次の無い映画ノベライズと、1〜4 巻を持つ漫画を見分けるため。`source_id` は組のハッシュ(`ndl:` + 10 桁)
- **手動で選んだ連携(「どれでもない」も)は、手動の作品名・著者と同じく「手動の決定」に数える**(`works.py _manual_involved()`)。強い証拠があっても自動統合せず提案に留め、利用者の決定が統合で落ちないようにする
- 決め直す経路(手動の選択の解除 `reset_link()`、粘る近道)も同じ規則を通す: 手動の連携から入った種別を前提にせず(外してから判定する)、種別が未決なら保留、作品の種別と食い違う候補は粘らない
- 自動連携は粘る(再取得で候補が残っていれば維持)。手動の連携は再取得で変えない(同じ候補が出たときに中身だけ更新)。手動の「どれでもない」は、その取得元へ問い合わせない

## 項目の埋め方(`spinebox/linking.py:520 _apply_field()`)

| 規則 | 理由 |
| --- | --- |
| 手動の項目は何があっても変えない(空にした項目も空のまま) | CLAUDE.md の不変条件。`manual` 列で見る。`tests/test_linking.py` が全項目で再取得・スキャン・再計算の前後を確かめる |
| 空欄は埋める(出所 `public_db`、確信度 = 連携の確信度、`evidence.link.sources` に取得元) | 外部は空欄だけを埋める |
| 名前(ファイル名・外側のアーカイブ名)由来の値は、**連携の確信度 ≥ 0.9 か、利用者が連携を選んだときだけ**置き換える。ただし現在の値が日本語でなく(ローマ字など)、公開 DB の値が日本語(かな・漢字を含む)で項目が作品名・著者なら、**確信度 ≥ 0.9 未満でも**置き換える(`_prefer_japanese_value()` #166)。現在の値が既に日本語なら、低確信度では置き換えず 0.9 の規則（日本語同士）に委ねる。置き換えた元の値は `evidence.replaced` に残し、連携を外すと戻す | 実データで作品名「Kakukaku Shikajika」→「かくかくしかじか」になる。日本語でない値・作品名・著者以外の項目は、確信度が低い連携で変えると取り返しがつかなくなる。置き換えた作品名は別名に残す(その名前の巻がまた新しい作品にならないように) |
| 取得元の優先: 種別・出版社は NDL、巻数は AniList → MangaUpdates、ジャンル・タグは MangaUpdates と AniList の和(重複除去・上限つき)。あらすじは入れない(下の「あらすじの廃止」) | 取得元の強みで分けた(NDL は書誌、他は作品単位の分類) |
| 別名は公開 DB の名前から(ローマ字と日本語を先に、最大 6、3 文字未満・非対応文字種は除く) | 別名の一致が名寄せの証拠([[work-grouping]])になるので、タイ語など使えない綴りは入れない。公開 DB の別名で作品が自動統合されることがある(確信度は連携の確信度)。連携を外す・別の候補にすると、その別名も外す(手動の別名・利用者が外した別名は触らない) |
| 巻の書誌(出版社・レーベル・発売日・ISBN・巻次)は、NDL の連携がある作品の**巻番号が単独で分かる巻**だけに入れる(`_apply_volumes()`) | 範囲(`v01-03`)の巻や、名前と中身の食い違い([[work-grouping]] の findings)がある巻には入れない。巻番号は名前から読んだ候補にすぎない。同じ番号の重複スキャンには同じ書誌が入る |

## 日本語での表示(#74)

AniList / MangaUpdates のジャンル・タグは英語、MangaUpdates の出版社はローマ字(`Overlap`)で来る。利用者の要望(#74)で、反映のときに日本語にする。
入口は `spinebox/ja_terms.py:510 term_ja()` / `spinebox/ja_terms.py:520 publisher_ja()`(対応表)と `spinebox/linking.py:462 _desired_fields()`(反映で使う)。

| 規則 | 理由 |
| --- | --- |
| **訳すのは反映(`apply_work`)と、候補を画面へ出すとき(`spinebox/works.py:1419 _link_json()`)だけ。** `work_links.item` / `candidates` と生の応答は英語のまま | 対応表を足す・設定を変えると、取り直さずに次の反映(起動時・スキャン後)で全作品に効く。取得し直しは外部への要求とレート制限を食う |
| ジャンル・タグは対応表(AniList・MangaUpdates のジャンルは全語、タグは頻出のもの)で引く。表記の揺れ(`Teacher/s` と `Teacher`、ハイフン、全角、大文字小文字)は畳み、訳して同じになった語は 1 つにまとめる | MangaUpdates のタグ(categories)は利用者投稿で数千語あり全部は持てない。記録済みの応答に出る語はすべて引ける(`tests/test_ja_terms.py` が確かめる) |
| **対応表に無い語は既定で入れない**(`[metadata] untranslated_terms = "hide"`。`keep` で英語のまま入れる) | 利用者が日本語で揃えたいと要望した。元の値は残っているので、`keep` にすれば次の起動で戻る。隠した語は絞り込みの候補にも出ない |
| 出版社は NDL(日本語)が先。NDL の連携が無く MangaUpdates の原版元だけのときは、ローマ字名を対応表で日本語にする。**対応が無いローマ字名はそのまま出す** | 英語表記が入る経路はこれだけ(NDL が確認待ち・該当なしの作品)。出版社名は固有名なので、隠すより読める綴りで残す |
| 手動の項目は訳さない(英語で手入力した値も英語のまま) | 不変条件。訳すのは公開 DB から入る値だけ |

**機械翻訳は入れていない。** 外部サービス(翻訳 API)へ蔵書の情報を送ることになるため。

## あらすじの廃止(#82)

あらすじは作品の項目にしない(利用者の判断、2026-11-02)。今の 3 取得元で得られるあらすじは英語だけで
(NDL の OpenSearch に内容紹介は無い。[[metadata-sources]])、#74 では英語のまま折りたたんでいたが、機械翻訳(外部送信)は使わないので廃止した。

| 規則 | 理由 |
| --- | --- |
| **取得元クライアントはあらすじを読み取らない**(`MetadataItem` に項目が無い)。結線も入れない | 読み取って使わない値は、`work_links.item` / `candidates` に溜まり続け、また使う実装を誘う。英語のあらすじが要る用途が今は無い |
| AniList の GraphQL のクエリからは `description` を外していない(`spinebox/metadata/anilist.py` `QUERY`) | クエリは要求の本文で、本文は保存済みの生応答の鍵(`spinebox/metadata/http.py:73 key()`(`SourceRequest`))に入る。外すと保存済みの AniList の応答が全部使えなくなり、取り直しになる |
| **既に DB にあるあらすじの行(`work_fields` の `synopsis`)は消さない。** API・作品の詳細・編集・自動に戻す・統合での引き継ぎ・全文検索には出さない(`spinebox/works.py` `RETIRED_FIELDS`) | 手で書いたあらすじもありうる。元に戻せない削除をしない。生の応答(`metadata_responses`)と、廃止前に保存した候補の中身(`work_links.item`)のあらすじもそのまま |
| 廃止したあらすじの手動の行は「手動が絡む」(`spinebox/works.py` `_manual_involved()`)に数えない | 画面から見えず「自動に戻す」もできない行で、確信度の高い自動統合が止まり続けるのを避ける。統合されても行は吸収された作品に残る(消えない) |
| 索引からはマイグレーション 11 で外す。あらすじの行を持つ作品にだけ `work_search_dirty` の印を立て、次の検索の前に索引し直す | 索引は派生データ([[work-search]])。全件の作り直しは要らない |
| 設定 `[metadata] english_synopsis` は廃止。古い設定ファイルに残っていても値によらず無視し、読み込みで警告を 1 回ログに出す(`spinebox/config.py` `RETIRED_METADATA_KEYS`) | サーバー機の `config.local.toml` に残っていても常駐が起動しなくならないように |

日本語のあらすじを持つ取得元(楽天ブックスの商品説明など。API キーが要る)を足すなら、項目を戻すことになる。

## 手動の編集と「自動に戻す」

`spinebox/works.py:841 edit_fields()` は手動で保存し、直す前の値を `evidence.previous` に退避する。`spinebox/works.py:880 reset_field()` が復元し、無ければ空に戻す(その後 `apply_work` が公開 DB の値を入れ直す)。
作品名は直す前の名前が残っていないと戻せない(409)。巻の書誌は `edit_volume_fields()` / `reset_volume_field()` で同じ。
統合(`merge_works`)は手動の項目を優先して引き継ぎ、連携も `_merge_links()` で移す。整理(CBZ 化)で巻が作り直されても、`transfer_volume_fields()` が書誌を引き継ぐ。

## 取得元が落ちているとき

失敗は**例外にせず**、作品 × 取得元の `work_links.failure`(種類・メッセージ・HTTP 状態・再試行秒・時刻)に記録し、成功すれば消す。すでに入った値と連携は失敗で変えない。
有効期限切れでも取得元が落ちていれば古い保存済みの応答を使い(`stale`)、画面に出す。想定外の例外も `internal` として記録して続ける(`fetch_work` は raise しない)。
全作品の取得(`POST /api/works/metadata/fetch`)は 1 本ずつ直列で、既定の最小間隔(NDL 1.0 秒・AniList 2.0 秒・MangaUpdates 1.0 秒)を守る。
対象は未取得・失敗から `retry_hours` 経過・成功から `recheck_days` 経過の作品(`works_needing_fetch()`)。裏の定期取得は既定で無効(`[metadata] background`)。取得はどの経路もデータ管理のジョブとして 1 本ずつ動き、履歴に残る(中止・失敗でも取得できた分は反映する。[[data-jobs]])。

## 保存場所(全文検索・絞り込みの入口)

後続の全文検索・絞り込みの Issue はここに乗せる。

| 何 | どこ |
| --- | --- |
| 作品の項目(`title` `author` `kind` `publisher` `genres` `tags` `total_volumes`。廃止した `synopsis` の行も残っている)と出所・手動・確信度 | `work_fields`(マイグレーション 6 の既存表。`genres` / `tags` は JSON 配列なので `json_each(value)` で展開。定数は `spinebox/works.py:32 FIELD_KIND` ほか) |
| 作品の別名(公開 DB 由来を含む) | `work_aliases`(`source = 'public_db'`) |
| 巻の書誌(`publisher` `label` `released` `isbn` `volume_label` `subtitle`) | `volume_fields`(マイグレーション 7) |
| 連携・候補・失敗 | `work_links`(マイグレーション 7。`candidates` `item` は JSON) |
| 生の応答 | `metadata_responses`([[metadata-clients]]) |

## 使う側

- [[follow]] は NDL の連携だけを短い有効期限で取り直し(`fetch_work(..., sources=("ndl",))`)、連携した組の巻ごとの書誌から蔵書に無い巻番号を数える。連携の規則は変えずに乗っている

## 却下した案

- **連携を 1 作品 1 行(取得元をまとめる)にする**: 取得元ごとに候補も失敗も違い、NDL の割れを AniList が引きずる構造になる。取得元ごとの行にして、保留の連鎖(`kind_unresolved`)だけを明示した
- **確信度が高ければ作品名を常に置き換える/一切置き換えない**: 前者は低い確信度で名前が変わる事故、後者はローマ字のファイル名の作品が日本語名にならず名寄せも進まない。「0.9 以上か利用者が選んだとき」にした
- **スキャンのたびに公開 DB を引く**: スキャン・閲覧を外部の障害に巻き込み、レート制限も食う。取得は明示操作(か設定した定期取得)に限った
- **取得元のクライアント(パーサ)で日本語にする**(#74): 保存する連携の中身が訳した値になり、対応表を直しても取り直すまで直らない。反映で訳せば起動で全作品に効く
- **画面(フロント)でだけ訳す**(#74): 絞り込み・全文検索の値が英語のまま残り、「日常」で絞れない。`work_fields` に訳した値を入れた
- **NDL を 1 冊ずつ連携の単位にする**: 作品に 1〜10 件の書誌が並び、どれを選ぶかを巻ごとに利用者に聞くことになる。組にして 1 回の確認で済ませた
