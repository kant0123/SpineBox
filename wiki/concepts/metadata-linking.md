# 公開 DB の結線(`spinebox/linking.py`)

[[metadata-clients]] が返す候補を、作品(`works`)と巻(`volumes`)の項目へ結ぶ(GOAL.md フェーズ 3「公開データベースから埋まる」、#50)。
クライアントは候補と確からしさを返すだけで、**どれを採るか・どう埋めるかはここ**。取得元の癖は [[metadata-sources]]、作品・項目の持ち方は [[work-grouping]]。

## 全体像

```
fetch_work(作品, 取得元)  ← 唯一ネットワークに触る。データ管理のジョブ/作品ページの「情報を取得」/裏の定期取得からだけ
   │  候補を作って work_links に保存(自動で連携 / 確認待ち / 該当なし / 失敗の記録)
   ▼
apply_work(作品)          ← DB だけで完結・冪等。fetch・choose・reset・スキャン後に走る
   │  連携から work_fields / work_aliases / volume_fields を導出
   ▼
```

**スキャン・閲覧・編集はネットワークに触らない**(CLAUDE.md「取得失敗でスキャンと閲覧を止めない」)。`apply_work` は連携の中身(保存済み)の純関数なので、
スキャンで巻が増えれば `apply_all` が新しい巻へ書誌を入れ、連携を外せば公開 DB 由来の値だけが消える。

## 連携の決め方(`spinebox/linking.py:187 decide()`)

- 取得元ごとに 1 作品 1 行(`work_links`: `status` = `linked` / `pending` / `none`)。`manual` は利用者が選んだ連携
- **自動で連携するのは、最良候補の確からしさ ≥ 0.75 かつ 2 位との差 ≥ 0.15**(`AUTO_LINK_MIN` / `LINK_MARGIN`)。足りなければ `pending`(確認待ち)で、0.5 以上の候補を最大 5 件見せる。
  数値の根拠は実データ(`_参考/サンプル本` の 2 作品)で、かくかくしかじかは 1.0 対 0.71、お気楽領主は漫画 1.0 対小説 1.0 の同点。閾値の調整は `tests/test_linking.py` の同点・僅差のケースを見てから
- **首位が 1.0 で拮抗しても、手元の最大巻番号(2 以上)を全巻数が覆う候補が 1 件だけなら自動で連携する**(`spinebox/linking.py:169 _volume_tiebreak()`、#254)。
  実データの人形の国で、AniList に同名・同作者の 2 件(巻数なしの前身と全 9 巻の本編)が 1.0 で並び、確認待ちに残った。
  選ぶのは 1.0 どうしの同点からだけ(1.0 未満の次点は全巻数が合っても選ばない)。全巻数が空の候補は「覆う」に数えない(連載中は空)。拮抗する候補の種別が割れている・不明なときと、保留(`kind_unresolved`)中は従来どおり確認待ち
- 作品の種別(`kind`)が分かっていれば、種別の違う候補は除く
- **名前の部分一致は、短い方の名前が長い方の先頭にあるときだけ強めに見る**(`spinebox/metadata/match.py:62 title_score()`)。
  副題・巻数が後ろに付く形(`作品名` と `作品名 生産系魔術で…`)は同じ作品の別表記とみなすが、末尾・途中にしか無い一致は
  似ている度だけで採点する。実データ(#158)では `57 files`(ファイル数の見出し)に MangaUpdates の別名 `FILES` が
  末尾で含まれるだけで 0.8143 になり、自動連携の基準(0.75)を超えていた
- **種別が決まっていない作品で国立国会図書館サーチが漫画と小説で割れているときは、メディア芸術データベース / Bangumi も確認待ちにする(`hold = "kind_unresolved"`、`kind_unresolved()`)。**
  お気楽領主は MangaUpdates(#278 で置き換える前)の漫画が名前完全一致で差が付き、先に自動連携して種別と著者を書いてしまった(NDL の割れを無視した誤り)。NDL の候補を選ぶと、次の取得(保存済みの応答を使うので通信は出ない)で残りが自動で決まる
- 国立国会図書館サーチは 1 冊ずつの書誌なので、**(種別・作品名・シリーズ名・著者)が同じものを「組」にして連携の単位にする**(`_ndl_groups()`)。組の確からしさ = 最良の巻 × 0.85 + 手元の巻番号を組が覆う割合 × 0.15。
  同じ名前で巻次の無い映画ノベライズと、1〜4 巻を持つ漫画を見分けるため。`source_id` は組のハッシュ(`ndl:` + 10 桁)
- **手動で選んだ連携(「どれでもない」も)は、手動の作品名・著者と同じく「手動の決定」に数える**(`works.py _manual_involved()`)。強い証拠があっても自動統合せず提案に留め、利用者の決定が統合で落ちないようにする
- 決め直す経路(手動の選択の解除 `reset_link()`、粘る近道)も同じ規則を通す: 手動の連携から入った種別を前提にせず(外してから判定する)、種別が未決なら保留、作品の種別と食い違う候補は粘らない
- 自動連携は粘る(再取得で候補が残っていれば維持)。手動の連携は再取得で変えない(同じ候補が出たときに中身だけ更新)。手動の「どれでもない」は、その取得元へ問い合わせない

## 項目の埋め方(`spinebox/linking.py:568 _apply_field()`)

| 規則 | 理由 |
| --- | --- |
| 手動の項目は何があっても変えない(空にした項目も空のまま) | CLAUDE.md の不変条件。`manual` 列で見る。`tests/test_linking.py` が全項目で再取得・スキャン・再計算の前後を確かめる |
| 空欄は埋める(出所 `public_db`、確信度 = 連携の確信度、`evidence.link.sources` に取得元) | 外部は空欄だけを埋める |
| 名前(ファイル名・外側のアーカイブ名)由来の値は、**連携の確信度 ≥ 0.9 か、利用者が連携を選んだときだけ**置き換える。ただし現在の値が日本語でなく(ローマ字など)、公開 DB の値が日本語(かな・漢字を含む)で項目が作品名・著者なら、**確信度 ≥ 0.9 未満でも**置き換える(`_prefer_japanese_value()` #166)。現在の値が既に日本語なら、低確信度では置き換えず 0.9 の規則（日本語同士）に委ねる。置き換えた元の値は `evidence.replaced` に残し、連携を外すと戻す | 実データで作品名「Kakukaku Shikajika」→「かくかくしかじか」になる。日本語でない値・作品名・著者以外の項目は、確信度が低い連携で変えると取り返しがつかなくなる。置き換えた作品名は別名に残す(その名前の巻がまた新しい作品にならないように) |
| 取得元の優先: 種別・出版社は NDL → メディア芸術データベース → Bangumi、巻数は メディア芸術データベース → Bangumi。ジャンル・タグはメディア芸術データベース・Bangumi が持たないため ehentai / nhentai の和(重複除去・上限つき、既定では無効)。あらすじは入れない(下の「あらすじの廃止」) | 取得元の強みで分けた(NDL は書誌、他は作品単位の分類)。ジャンル・タグの構造化された語彙を持つ取得元(AniList・MangaUpdates)は #278 で置き換えた |
| 別名は公開 DB の名前から(ローマ字と日本語を先に、最大 6、3 文字未満・非対応文字種は除く) | 別名の一致が名寄せの証拠([[work-grouping]])になるので、タイ語など使えない綴りは入れない。公開 DB の別名で作品が自動統合されることがある(確信度は連携の確信度)。連携を外す・別の候補にすると、その別名も外す(手動の別名・利用者が外した別名は触らない) |
| 巻の書誌(出版社・レーベル・発売日・ISBN・巻次)は、NDL の連携がある作品の**巻番号が単独で分かる巻**だけに入れる(`_apply_volumes()`) | 範囲(`v01-03`)の巻や、名前と中身の食い違い([[work-grouping]] の findings)がある巻には入れない。巻番号は名前から読んだ候補にすぎない。同じ番号の重複スキャンには同じ書誌が入る |

## 同人誌の取得元(#275)

`ehentai` / `nhentai` は `SEARCH_ORDER` の末尾に置き、項目の優先は**既存の取得元の後ろ**(作品名・著者・種別・出版社は NDL → メディア芸術データベース → Bangumi → E-Hentai → nHentai、ジャンル・タグは和集合の末尾)。
同人誌は NDL・メディア芸術データベース・Bangumi をほぼ引けないので、実際にはこの 2 つだけが連携する。両方が連携すれば E-Hentai(詳細が 1 要求で取れる)を先にした。

- **著者はファイル名の書式のまま `サークル (作者)` で入れる。** 名前由来の値と同じ表記になるので、確信度が高くても置き換えの対象にならない(揺らさない)。サークルは出版社に入れる
- **同じ本の翻訳版・再アップロードは取得元のクライアントが 1 件にまとめる**([[metadata-sources]])。まとめないと首位が 1.0 で拮抗し、自動で連携できず確認待ちが増える
- ファイル名側は `spinebox/naming.py:384 parse_work_name()` が読む。**先頭の `(C70)` など丸括弧の開催イベントは、直後に `[サークル (作者)]` が続くときは著者にしない**(それまでは `C70` が著者になり、著者の照合が必ず外れた)。[[work-grouping]]

## 日本語での表示(#74)

AniList / MangaUpdates(#278 で置き換える前)のジャンル・タグは英語、MangaUpdates の出版社はローマ字(`Overlap`)で来ていた。利用者の要望(#74)で、反映のときに日本語にする仕組みを作った。
今の既定の取得元(メディア芸術データベース・Bangumi)は構造化されたジャンル・タグを持たず、出版社も日本語で来るため、この仕組みを実際に使うのは既定で無効の ehentai / nhentai(英語のタグ)だけになった(#278)。
入口は `spinebox/ja_terms.py:510 term_ja()` / `spinebox/ja_terms.py:520 publisher_ja()`(対応表)と `spinebox/linking.py:510 _desired_fields()`(反映で使う)。

| 規則 | 理由 |
| --- | --- |
| **訳すのは反映(`apply_work`)と、候補を画面へ出すとき(`spinebox/works.py:2085 _link_json()`)だけ。** `work_links.item` / `candidates` と生の応答は英語のまま | 対応表を足す・設定を変えると、取り直さずに次の反映(起動時・スキャン後)で全作品に効く。取得し直しは外部への要求とレート制限を食う |
| ジャンル・タグは対応表(導入時は AniList・MangaUpdates の全ジャンル語彙で作った。タグは頻出のもの)で引く。表記の揺れ(`Teacher/s` と `Teacher`、ハイフン、全角、大文字小文字)は畳み、訳して同じになった語は 1 つにまとめる | 利用者投稿のタグは数千語あり全部は持てない。記録済みの応答に出る語はすべて引ける(`tests/test_ja_terms.py` が確かめる) |
| **対応表に無い語は既定で入れない**(`[metadata] untranslated_terms = "hide"`。`keep` で元の表記のまま入れる) | 利用者が日本語で揃えたいと要望した。元の値は残っているので、`keep` にすれば次の起動で戻る。隠した語は絞り込みの候補にも出ない。**簡体字中国語(Bangumi のタグ)は対応表の対象外で、`is_japanese()` が仮名の無い中国語を日本語と誤認するため既定でも隠れない**(そのためタグ自体を読み取らない。#284) |
| 出版社は NDL(日本語)が先。ローマ字名(MangaUpdates の原版元など)しか無いときは、対応表で日本語にする。**対応が無いローマ字名はそのまま出す** | 出版社名は固有名なので、隠すより読める綴りで残す |
| 手動の項目は訳さない(英語で手入力した値も英語のまま) | 不変条件。訳すのは公開 DB から入る値だけ |

**機械翻訳は入れていない。** 外部サービス(翻訳 API)へ蔵書の情報を送ることになるため。

## あらすじの廃止(#82)

あらすじは作品の項目にしない(利用者の判断、2026-11-02)。当時の取得元で得られるあらすじは英語だけで
(NDL の OpenSearch に内容紹介は無い。[[metadata-sources]])、#74 では英語のまま折りたたんでいたが、機械翻訳(外部送信)は使わないので廃止した。
**Bangumi は日本語のあらすじを持つが、#278 で置き換えたときも読み取る対象には戻さなかった**(この方針を変える判断はしていない。`MetadataItem` にあらすじの項目を戻すスキーマ変更が要る)。

| 規則 | 理由 |
| --- | --- |
| **取得元クライアントはあらすじを読み取らない**(`MetadataItem` に項目が無い)。結線も入れない | 読み取って使わない値は、`work_links.item` / `candidates` に溜まり続け、また使う実装を誘う |
| **既に DB にあるあらすじの行(`work_fields` の `synopsis`)は消さない。** API・作品の詳細・編集・自動に戻す・統合での引き継ぎ・全文検索には出さない(`spinebox/works.py` `RETIRED_FIELDS`) | 手で書いたあらすじもありうる。元に戻せない削除をしない。生の応答(`metadata_responses`)と、廃止前に保存した候補の中身(`work_links.item`)のあらすじもそのまま |
| 廃止したあらすじの手動の行は「手動が絡む」(`spinebox/works.py` `_manual_involved()`)に数えない | 画面から見えず「自動に戻す」もできない行で、確信度の高い自動統合が止まり続けるのを避ける。統合されても行は吸収された作品に残る(消えない) |
| 索引からはマイグレーション 11 で外す。あらすじの行を持つ作品にだけ `work_search_dirty` の印を立て、次の検索の前に索引し直す | 索引は派生データ([[work-search]])。全件の作り直しは要らない |
| 設定 `[metadata] english_synopsis` は廃止。古い設定ファイルに残っていても値によらず無視し、読み込みで警告を 1 回ログに出す(`spinebox/config.py` `RETIRED_METADATA_KEYS`) | サーバー機の `config.local.toml` に残っていても常駐が起動しなくならないように |

日本語のあらすじを持つ取得元(楽天ブックスの商品説明など。API キーが要る)を足すなら、項目を戻すことになる。

## 手動の編集と「自動に戻す」

`spinebox/works.py:1361 edit_fields()` は手動で保存し、直す前の値を `evidence.previous` に退避する。`spinebox/works.py:1400 reset_field()` が復元し、無ければ空に戻す(その後 `apply_work` が公開 DB の値を入れ直す)。
作品名は直す前の名前が残っていないと戻せない(409)。巻の書誌は `edit_volume_fields()` / `reset_volume_field()` で同じ。
統合(`merge_works`)は手動の項目を優先して引き継ぎ、連携も `_merge_links()` で移す。整理(CBZ 化)で巻が作り直されても、`transfer_volume_fields()` が書誌を引き継ぐ。

## 取得元が落ちているとき

失敗は**例外にせず**、作品 × 取得元の `work_links.failure`(種類・メッセージ・HTTP 状態・再試行秒・時刻)に記録し、成功すれば消す。すでに入った値と連携は失敗で変えない。
有効期限切れでも取得元が落ちていれば古い保存済みの応答を使い(`stale`)、画面に出す。想定外の例外も `internal` として記録して続ける(`fetch_work` は raise しない)。
全作品の取得(`POST /api/works/metadata/fetch`)は 1 本ずつ直列で(連携したところで残りの取得元を飛ばす。下の「全作品をまとめて取るとき」)、既定の最小間隔(NDL 1.0 秒・メディア芸術データベース 1.0 秒・Bangumi 1.0 秒)を守る。
対象は未取得・失敗から `retry_hours` 経過・成功から `recheck_days` 経過の作品(`works_needing_fetch()`)。裏の定期取得は既定で無効(`[metadata] background`)。取得はどの経路もデータ管理のジョブとして 1 本ずつ動き、履歴に残る(中止・失敗でも取得できた分は反映する。[[data-jobs]])。

## 全作品をまとめて取るとき(軽い取得。#288)

データ管理のジョブ(全体の同期・足りない作品を補う・作品情報のみ補完・全作品を取り直す)と裏の定期取得は `fetch_work(quick=True)` で引く。
**作品ページの「情報を取得」は全取得元を引く**(`spinebox/datajobs.py:198 _metadata()` が `ids` の有無で分ける)。

| 規則 | 理由 |
| --- | --- |
| 検索の順(`SEARCH_ORDER`)に引き、**連携が決まって(自動でも手動でも)確信度 0.9 以上**(`QUICK_STOP_MIN`、`spinebox/linking.py:354 _settles()`)になったら、残りの取得元は引かず `skipped` で返す。行は作らない・変えない | 本番(1,102 作品)で 1 作品 約 30 秒、全件で約 9 時間かかった。0.9 は名前由来の値を置き換える基準(`REPLACE_MIN`)と同じ。**確認待ちは確信度が高くても止めない**(本番で 0.9 以上の確認待ちが E-Hentai 38 件・nHentai 46 件。同点・僅差の候補が並んでいる)。連携済みの確信度はほぼ 0.95 以上なので、閾値を 0.75〜0.9 で動かしても止まる作品はほとんど変わらない |
| 取得が失敗している連携(`failure` あり)では止めない | 古い連携を根拠に残りを飛ばし続けない |
| `works_needing_fetch()` は、止まる連携がある作品を**検索の順で最初のその連携の取得日時だけ**で決める | 飛ばした取得元は行が無い・古いままなので、「未取得」「期限切れ」に数えると毎回対象に戻る。その連携より前の取得元の失敗も、再確認の期限(`recheck_days`)までは取り直さない |
| 取得元には軽い検索(`SearchQuery.quick`)を頼む。**連携・確認待ちの行がある取得元は、軽くしない** | 軽い検索は 0 件のときの引き直しを省く([[metadata-clients]])。引き直しで見つけた連携・候補を、30 日ごとの取り直しで失わないため |
| 順は NDL → メディア芸術データベース → Bangumi → E-Hentai → nHentai。**NDL は遅い(1 要求 約 6 秒)が先頭のまま** | `kind_unresolved()` の保留が「NDL の候補を先に見ている」ことを前提にしている。NDL を後ろへ回すと、漫画と小説が割れている作品をほかの取得元が先に自動連携する(お気楽領主の誤りの再発)。NDL が遅くて困るときは設定の `sources` から外す。同人誌は E-Hentai(1 検索 2 要求)を nHentai(検索 + 詳細)より先に引く |

却下した案:

- **飛ばした取得元に `skipped` の行を書く**: `work_links.status` の値が増え、画面・統合(`_merge_links()`)・確認の一覧のすべてで扱いが要る。飛ばしたかどうかは既存の行から決められる
- **確からしさ(点数)だけで止める**: 同点・僅差で確認待ちの作品が、次の取得元で決まる機会を失う
- **同人誌の書式の名前だけ同人誌の取得元を先に引く**: 名前の書式は候補にすぎず(番号だけのフォルダ名が多い)、順が作品ごとに変わると `kind_unresolved()` の前提も崩れる。メディア芸術データベース・Bangumi は 1 要求 1 秒未満なので、先に引く無駄は小さい

期待した効果(本番 856 作品の取得記録からの試算。実測ではない): 同人誌の取得元の待ちが 1 作品 約 25 秒 → 約 12 秒。E-Hentai が 0.9 以上で連携して nHentai を飛ばせるのは 31%。

## 保存場所(全文検索・絞り込みの入口)

後続の全文検索・絞り込みの Issue はここに乗せる。

| 何 | どこ |
| --- | --- |
| 作品の項目(`title` `author` `kind` `publisher` `genres` `tags` `total_volumes`。廃止した `synopsis` の行も残っている)と出所・手動・確信度 | `work_fields`(マイグレーション 6 の既存表。`genres` / `tags` は JSON 配列なので `json_each(value)` で展開。定数は `spinebox/works.py:41 FIELD_KIND` ほか) |

## 使う側

- [[follow]] は NDL の連携だけを短い有効期限で取り直し(`fetch_work(..., sources=("ndl",))`)、連携した組の巻ごとの書誌から蔵書に無い巻番号を数える。連携の規則は変えずに乗っている

- 確認待ち(`pending`)の作品は、作品ページのほか確認の画面(`#/review`。#207)でまとめて選べる。一覧は `GET /api/review/links`(`spinebox/app.py:784 review_links()`)で、選ぶ API は作品ページと同じ([[frontend]])

## 却下した案

- **連携を 1 作品 1 行(取得元をまとめる)にする**: 取得元ごとに候補も失敗も違い、NDL の割れを AniList が引きずる構造になる。取得元ごとの行にして、保留の連鎖(`kind_unresolved`)だけを明示した
- **確信度が高ければ作品名を常に置き換える/一切置き換えない**: 前者は低い確信度で名前が変わる事故、後者はローマ字のファイル名の作品が日本語名にならず名寄せも進まない。「0.9 以上か利用者が選んだとき」にした
- **スキャンのたびに公開 DB を引く**: スキャン・閲覧を外部の障害に巻き込み、レート制限も食う。取得は明示操作(か設定した定期取得)に限った
- **取得元のクライアント(パーサ)で日本語にする**(#74): 保存する連携の中身が訳した値になり、対応表を直しても取り直すまで直らない。反映で訳せば起動で全作品に効く
- **画面(フロント)でだけ訳す**(#74): 絞り込み・全文検索の値が英語のまま残り、「日常」で絞れない。`work_fields` に訳した値を入れた
- **NDL を 1 冊ずつ連携の単位にする**: 作品に 1〜10 件の書誌が並び、どれを選ぶかを巻ごとに利用者に聞くことになる。組にして 1 回の確認で済ませた
