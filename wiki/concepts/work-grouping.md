# 作品の名寄せ(`spinebox/works.py`)

巻を「作品」にまとめ、作品名・著者・別名と、まとめた根拠を持つ(GOAL.md フェーズ 3)。
作品ページは巻を番号順に並べ、同じ番号の巻は重複としてまとめ、欠けている巻を示す。

## 内容

- **作品は派生データ。** 巻の名前から作る。名前は候補なので([[volume-split]] の巻番号と同じ扱い)、
  作品の項目・別名・巻の割り当てはどれも 1 件ごとに `source`・`manual`・`confidence`・`evidence`(JSON)を持つ。
  入口: `spinebox/works.py:856 sync()`(割り当て `_assign_volumes` → 外側の名前の別名 `_container_aliases` → 提案と自動統合 `_propose_and_merge`)
- **保存先。** 作品 `works`(統合されたものは `merged_into` でリダイレクト)、項目 `work_fields`(title・author を行で持つ。
  項目を足すときは行を足すだけで列は足さない)、別名 `work_aliases`、巻の割り当て `work_volumes`(巻あたり 1 行)、
  統合の提案と履歴 `work_merge_proposals`。`spinebox/db.py:40 MIGRATIONS` の版 6。「手動か」「出所」は
  項目・別名・割り当ての全部が持つので、公開 DB の取得([[metadata-linking]])・手動編集の保護・全文検索はこの列に乗せる
- **名前の読み方。** `spinebox/naming.py:373 parse_work_name()` が巻番号・配布元・タグ・拡張子を落とした作品名と著者の候補を返し、
  同人誌の先頭の `(C70)` `(例大祭12)` は開催イベントで、直後に `[サークル (作者)]` が続く丸括弧は著者にしない(`parts` では `tag`。#275)。著者欄は `サークル (作者)` のまま持つ。
  著者は作品を作るときにだけ読むので、この修正より前に作られた作品の著者(`C70` など)は読み直されない(公開 DB の連携が確信度 0.9 以上なら置き換わる。検索側はサークル名つきの検索が 0 件なら作品名だけで引き直すので、連携自体は止まらない)。
  `spinebox/naming.py:262 normalize_title()` が突き合わせ用に正規化する(大文字小文字・全角半角・かな種の差を畳む)。
  簡体字の巻表示・話表示(`卷` `话`)は正規の字(`巻` `話`)と同じに読む(`spinebox/naming.py _fold_chars`)。
  巻の**自分の名前**(巻 → 入れ子 → 外側の順で最初に作品名と読めたもの)が既存の作品名・別名と一致すればその作品、無ければ新しい作品
- **小数点の巻は番号なしの巻として作品に入れる。** `第04.5巻` や `Chapter 002.2`、`ch.02.5`、`第02.5話` などの小数点の巻・話・チャプターは整数の `number_start`/`number_end` で持てないので番号にせず
  (`parse_number()` は小数点の内側の数字を拾わない)、作品名にも残さない(`parse_work_name()` が `_find_decimal()` で該当部分を落とす。#220)。
  名前全体がチャプター表記単体(`Chapter 002.2`)なら作品名候補が `None` となり、外側の親フォルダ名が作品名として採用される。
  欠け巻・重複枠の計算には入れず、番号の読めない巻として扱う。
  既存 DB の小数点の巻番号は、名寄せの `_apply_trailing_numbers()` が `parse_number()` で読めない番号として消す
  (スキャンし直さなくても直る。番号を持たない巻の行は触らないので冪等)
- **数の数えた名前は作品名にしない。** 配布元の接頭辞(`DLRAW.AC_`)を落とすと残る `57 files` `4 cover` のような名前は、
  ファイル数・ページ数の見出しで、作品名ではない(`spinebox/naming.py _COUNT_NAME`)。実データ(#158)では 1〜109 files などの
  74 作品・184 巻がこれでできていた。自分の名前が読めないので、外側の名前(`あつまれ!ふしぎ研究部 第01-20巻.rar`)から
  作品を読む(確信度 0.6)か、どこからも読めなければ「作品にならなかった巻」になる。
  この名前を読ませると、同じ公開 DB 項目に linked した 73 の作品どうしが別名で結ばれて 2000 組超の提案になり、
  末尾の番号の系列(#157)としては「files」1〜109 巻という作品にもなる
- **EPUB の構造名や汎用名、数字付きゴミ名は作品名・別名にしない。** `oebps` `ops` `metainf` `meta-inf` `epub` `mimetype` `cover` `image` `chapter` `episode` などは作品名として中身のない名前(`spinebox/naming.py JUNK_NAMES`)。また、`cover2` や `scans 01` のように単語の後ろに数字が付いた名前も作品名として中身のない名前(`spinebox/naming.py is_junk_name()`)。スキャン・分解で非コンテンツディレクトリとして巻にしない(`spinebox/scanner.py _NON_CONTENT_DIRS`、`SCAN_VERSION=7`、`ANALYSIS_VERSION=3`)。名寄せでは `_container_aliases` での別名登録や `_alias_evidence` での統合提案の根拠にしない。子フォルダが `cover2` のような名前でも作品名とならず親フォルダ名が採用される(#220)。さらに既存 DB に紛れ込んだ汚染を解消するため、`sync()` の冒頭で `is_junk_name()` に該当する自動別名、およびタイトルがジャンク名である非手動作品に付いた自動別名を `dismissed_at` で外し、ジャンク作品との確認待ち提案を削除する(#215, #220)。
- **確信度の目安。** 自分の名前から 0.9、巻の名前に作品名が無く外側の名前から読んだものは 0.6(`CONF_*` 定数)。
  外側のアーカイブ・フォルダの名前は、**その全部の巻が 1 つの作品に入っているときだけ**別名・著者の候補(0.5)にする
  (複数作品の入れ物の名前を別名にすると、別作品を混ぜる根拠になるため)
- **末尾の番号は、同じ名前の組がそろっているときだけ巻番号と読む。** `作品名 01` `作品名(3)` の形は
  名前だけでは巻番号と決められない(`Kitchen 2` が作品名のこともある)ので、`spinebox/naming.py parse_number()`
  は拾わず、`trailing_number()` が候補を返すだけ。`spinebox/works.py _trailing_series()` が、
  同じ名前で末尾の番号だけが違う巻が 2 つ以上ある組に限り、番号を `volumes.number_*` に入れて作品名から番号を落とす。
  組が 1 つに減れば番号は消え、作品名も元へ戻る(名前から導出した値なので残さない)。
  末尾の番号の後ろの括弧の装飾(`[レーベル]` `(レーベル)` `[AVIF]` など)と著者列(` - 著者 & 著者`)は装飾として落としてから読む。
  落とした部分は番号の根拠(`evidence`)に残す。数字の括弧(`(3)`)は従来どおり番号
  この形を読まないと 1 巻 = 1 作品に分裂し、公開 DB のシリーズ別名が全作品に付いて統合の提案が総当たりになる
  (実データ 2026-11-06: 4610 巻のうち 782 巻・73 組が該当。確認待ちの提案 6123 件のうち 3500 件超がこれだけで消えた)
- **作品の表示タイトルは、利用可能な限り日本語を正とする。** ローマ字(`okirakuryoshunotanoshiryochi` など)はファイル名由来の候補・別名として残し、
  表示タイトルと名寄せの代表(統合で残す作品)には使わない(#212)。日本語の出どころは公開 DB の連携・手動編集・コンテナ名。
  - 統合で残す作品は `spinebox/works.py:691 choose_survivor()` が決める: 手動の作品名 > 日本語の作品名 > 巻の多い方 > id の若い方。
  - ファイル名・外側の名前由来のローマ字の作品名・著者は、公開 DB の日本語で置き換える(確信度 0.9 未満でも)。
    `spinebox/linking.py:527 _prefer_japanese_value()`。日本語同士の置き換えは確信度 0.9 の規則に委ねる([[metadata-linking]])。
- **系列として読めた巻は、系列名を別名に持つだけの 1 巻作品に留めない。** 巻の割り当ては、読み直した作品名が
  **今の作品の名前のどれか**(別名を含む)と一致すれば動かさないが、公開 DB に linked した 1 巻 = 1 作品は
  系列名を別名として持つため、系列として読めても留まっていた(#162)。作品名が `系列名 + 末尾の番号` そのもの
  (例: `作品名 01`)で、手動の決定(作品名・巻の割り当て・公開 DB の連携)が絡まないなら系列名の作品へ付け替える
  (`spinebox/works.py _leaves_numbered_work()`)。付け替え先も、番号付きの作品(系列名を別名で持つだけ)には寄せず、
  無ければ系列名の作品を作る。留まると 1 巻 = 1 作品のまま、同じ公開 DB 項目の別名一致が総当たりの確認待ちになる
  (実データ 2026-11-06: 1187 作品・確認待ち 3949 件のうち、この形が 479 作品・65 シリーズ、3612 件がこれに絡んでいた)。
  付け替え先が既存の系列名の作品でも、`_merge_links()` が公開 DB の連携をその作品へ移す(新設の側だけに置かない)。
  また、小数点の巻を誤読して作った 1 巻の作品名(`… 第04`)は、手動でない・公開 DB が置き換えていない・末尾の番号を持たない
  とき、`_refresh_title()` が今の系列名へ直す(スキャンし直さなくても直る)

## EPUB の書誌(OPF)を名前より強い根拠にする(#251)

ファイル名がローマ字(読みを機械的に書き下したもの)の EPUB は、公開 DB でも当たらない。EPUB は自分の題を OPF に持つので、
スキャン(`spinebox/scanner.py _with_epub_meta()`、`SCAN_VERSION=11`)で `dc:title` / `dc:creator` / `dc:publisher` を読む。

- **`dc:title` を巻の名前にするのは、ファイル名が日本語を含まず `dc:title` が日本語を含むときだけ。** 日本語のファイル名は動かさず、
  日本語でない `dc:title`(`Unknown` など)も使わない。巻の名前になるので、作品名の確信度は巻自身の名前と同じ 0.9 で、
  その作品名で NDL などを引き直せる。元のファイル名は `name_raw` に残る
- **著者・出版社は巻の書誌(`volume_fields` の `author` / `publisher`、出所 `epub`)の候補。** 手動・公開 DB の値は上書きしない
  (前回の EPUB 由来だけ更新)。`author` は巻自身の名前で作品を決めたときだけ、作品の著者が空欄なら `_authors_of()` が埋める
  (名前に著者があればそれが先)。`author` は `VOLUME_FIELDS` に入れない(手で直す項目ではなく、公開 DB の反映の対象でもない)
- **同じ本の EPUB と保存ページの zip は、どちらも巻として残す。** zip を「登録不要」にするかは決めていない
  (中身が本文だけの保存ページで、`fragment_reason` の対象外。誤って本を消さない方に倒した)。表紙は EPUB を先にする([[cover-thumbnails]])

## 1 作品だけを収めた外側の名前で決める(#247)

蔵書は「作品名のフォルダ(多くは日本語)の下に、配布元ごとにばらばらの名前の巻が並ぶ」形が多い。巻の名前だけで
決めると、ローマ字の巻・日本語の巻・章のフォルダが別々の作品に割れる(実データ 2026-11-09: トップのフォルダ・
アーカイブ 20 件が 292 作品になった。`異世界迷宮で奴隷ハーレムを` は `第N部分:…` の 221 作品)。
入口: `spinebox/works.py _container_claims()`(割り当ての前に計算)と `_settle_claims()`(割り当ての後の片付け)。

- **外側の名前 N が「1 作品だけ」と言える条件。** N の下の巻ごとに、巻 → N の手前までで最初に作品名と読めた名前
  (系列名)を取る。章の見出し(`第4話 …` `第100部分:…` `chap 038` `特別編:…`。`naming.is_chapter_label()`)・
  断片(`is_fragment_name()`)・番号だけ(`17` `03s`)・保存ページのフォルダ(`16_files`)は系列名にしない。
  - N が日本語: 系列名が N と同じ・`N + 番号`・`N + …編`・`N 副題`(区切りの後ろ)なら N の巻。N と違う日本語の系列が
    2 つ以上あれば N はまとめのフォルダ(`小説`)で何もしない。違う日本語の系列が無く、ローマ字の系列が 1 つだけ
    (または N の名前の巻が 1 つでもある)ならローマ字の巻も N の巻。ローマ字の綴りの揺れ(`Sudachi no mao-jo` と
    `Sudachi_no_Maoujou`)は 1 つの系列と数える(`_romaji_variant()`。下の #263)
  - N がローマ字: 日本語の系列がちょうど 1 つで、N と違うローマ字の系列が無ければ全部その日本語の作品
  - 巻ごとに、日本語の作品名になる最も内側の N を採る(無ければ最も外側)。巻自身の名前(ローマ字)は作品の別名に残す
- **ローマ字と日本語は字面で結べないので、入れ物の中に他の候補が無いことを根拠にする。** 2 つのローマ字の系列が入る
  フォルダ(`技術本/…` に別々の本 2 冊)は混ぜない。短いフォルダ名 `ゾンビ` の下の `ゾンビだらけの…` と
  `ゾンビのあふれた…` は、`ゾンビ` の後ろが区切りでも番号でもないので別作品のまま
- **割り当ての後の片付け(`_settle_claims`)。** 手動の決定が絡む作品は動かさない。
  1. 同じ作品名の主張になった巻が複数の作品に残っていたら統合する。巻ごとの作品が公開 DB の系列名(`オーバーロード`)を
     別名に持つため、割り当てが「今の作品の名前と一致」で動かなかった組。残すのは手動の作品名 > 公開 DB の日本語 > 日本語 > 巻の多い方
  2. 外側の名前で巻が全部移って空になった作品は移り先へ統合する(ほかの付け替えで空になった作品は従来どおり提案の規則に任せる)。残すと、前の同期で付いた同じ外側の別名を持つ空の作品どうしが
     総当たりの確認待ちになる(`第N部分` の 221 作品で 24,347 件)
  3. 名前から付けた作品名(`source` が filename / merge / container)を外側の日本語の名前に揃える(全部の巻が同じ主張のとき)。
     今の読み方で作品名と読めない古い作品名(`bbjjf1 y files`)は、巻の名前の多数で付け直す
- **本の断片は巻にしない。** `spinebox/scanner.py fragment_reason()`(スキャンの切り出しと、内側アーカイブの分解
  `spinebox/library.py _units()` の両方)。目次・表紙・広告・1 文字だけの名前で 15 ページ以下、または保存ページのフォルダで
  1 ページだけの束(`57_files` のように本文の章のこともあるので 1 枚に限る)は、同じアーカイブ・フォルダにほかの巻があるときだけ巻にせず、`登録不要: …` の理由を scan_issues に残す
  (単独なら巻のまま。誤って本を消さない)。`SCAN_VERSION=9`、`ANALYSIS_VERSION=4`
- 結果(2026-11-09、テスト用蔵書): 292 作品・確認待ち 3 → 22 作品・確認待ち 0。割れた DB を同期し直しても、空の DB から
  同期しても同じまとまり、もう一度同期しても変化なし

## 本番の蔵書の初回同期で見つかった名前の形(#263)

本番(5,202 巻)の初回の全体同期は 496 作品(公開 DB なしで測ると 454)。外側の名前でまとめる仕組み(上)は効いていたが、
次の形が「別の系列が入っている」と数えられてまとめを止めていた。直したあと公開 DB なしで 299 作品・確認待ち 0。
入口は `spinebox/naming.py`(名前の読み)と `spinebox/works.py`(数え方・統合)、`spinebox/mojibake.py`(文字化け)。

- **直せない文字化けの名前 1 つが、日本語のフォルダのまとめを止める。** 展開ツールが一部のバイトを `+` `¦` に
  置き換えた cp437 の名前や `�` を含む名前は元に戻せない。`mojibake.looks_garbled()` で見分けて作品名にしない
  (`parse_work_name` が None を返すので、外側の名前に任せる)。語ごとに戻せる名前は語ごとに戻す(`_redecode_words()`。
  `ハンツー×トラッシュ 第10巻` は戻り、著者の括弧だけ化けたまま残る)。Shift_JIS を GBK で読んだ名前(`廡姧彮擭僒儞僨乕`)も戻す
- **ページの束・カラーページの名前(`単ページ` `color`)は作品名ではない**(`naming._JUNK_RAW`)。系列と数えると
  `ハンツー×トラッシュ` のフォルダがローマ字の巻をまとめられず、`単ページ` が名前の一致で別作品(`オーバーロード`)に入っていた
- **巻 1 冊を収めた入れ物の名前は、末尾の番号を落として系列名にする**(`works._without_trailing_number()`)。`動物人間 13.zip`
  `黄泉のツガイ 1.zip` `…（4）` は最も内側の日本語の名前として番号ごと作品名になっていた
- **ローマ字の綴りの揺れ**: 1 つの入れ物の中で、短い方の 8 割以上が共通の頭か、似ている度合い 0.8 以上なら同じ系列
  (`works._romaji_variant()`)。別作品の `isekainonbirisozai…` と `isekainonbirinoka` は頭の共通が 8 割に届かない。入れ物の外では使わない
- **日本語の名前の入れ物の中のローマ字の名前は、外側の名前の別名(0.5)に残す**(`_keep_container_romaji()`)。別の場所に
  そのローマ字の名前だけで届いた巻の作品(`DLRAW.AC_100_files` … の章 60 冊)が、作品名との完全一致で自動統合される。
  1 作品だけを収めた入れ物が作品を決めた巻の、巻自身の名前の別名(0.9)も同じ扱い(`_vouched_alias()`)
- **名前から付けた作品名どうしが完全一致する作品は自動統合する**(#268)。空の DB から同期すれば巻の割り当てで同じ作品に入る組で、
  前の読み方で別々に作った作品が読み直しで同じ作品名になったもの(本番: 1 巻だけの `DLRAW.AC あつまれ!…` が改名され、
  外側の名前で決めた確信度 0.8 の 328 巻の作品と確認待ちで残った)。手動・公開 DB の作品名が絡む組は確認待ちのまま
- **副題違いの同じ作品は統合する**(`_subtitle_evidence()`。根拠は `alias` の規則で `subtitle: true`、0.9)。日本語の作品名に
  区切り(空白・`~`・`、` など)と副題・番号を足しただけの作品どうし(`フシノカミ` と `フシノカミ ~辺境から始める文明再生記`)。
  区切りの無い続き(`異世界のんびり農家` と `異世界のんびり農家の日常`)は別作品。短い方が 4 文字未満なら拾わない。
  空白だけの区切り(`進撃の巨人 Before the fall`)は外伝のこともあるので確認待ち(0.8)。自動統合は記号の区切り(`~` `-` `:` `、`)だけ
- **1 冊だけの `作品名 3` は、作品名が日本語なら巻番号と読む**(`_trailing_series()`)。日本語の作品名は番号を空白で
  離さない(`3月のライオン` `狂四郎2030`)ので、空白の後ろの番号は巻番号と言える
- **名前の読み**(`naming._RULES`): 版の印の付いた番号(`_04w` `劇光仮面1s`。空白の後ろは 0 始まりのときだけ。`the 80s` は読まない)、
  番号の後ろの `&` 区切りの著者列(`… 1 十乃壱 天 & 菱川 さかく & だぶ竜`)、日本語の直後のローマ数字の巻(後ろに著者列があるときだけ)、
  語に続けた `…shimashitaChapter 015`(話)、
  小数点の章 `c43.5`。雑誌の号(`週刊少年サンデー 2021年36-37号` `2023年12月号`)は誌名を作品名にし、号を巻と読まない。
  日本語の作品名と副題の間の番号(`チュートリアルが始まる前に 1 ボスキャラ達を…`)は名前だけでは読まない(`クラスで 2 番目に…`
  は作品名)。同じ入れ物で数字だけ違う日本語の名前が並ぶときだけ同じ系列と数え、番号を落とした名前を作品名にする(`_differs_only_in_numbers()`)。
  先頭の整理用の印(`★`)・特典の括弧(`【電子限定特典付き】`)・著者の括弧の後ろの配布元(`[著者] DLRAW.AC_ 作品名`)を落とす
- **ソフトウェアの説明書きは巻にしない**(`scanner.software_doc_reason()`)。`README.txt` `CHANGELOG.txt` など決まった名前と、
  実行ファイル(`.exe` `.dll` `.jar` …)のあるフォルダの `.txt`。`登録不要: …` の理由を scan_issues に残す。`SCAN_VERSION=13`・`ANALYSIS_VERSION=7`

## 統合の規則

別々の作品が同じ本と言える根拠は 2 つ。

1. **重複候補の証拠**([[duplicate-detection]])。確信度は一致ページ比。巻番号まで同じ(`same_number`)ならその値、
   見た目だけ(`visual_only`)は 0.85 で頭打ち(`VISUAL_ONLY_CAP`)にして自動統合に回さない。却下された重複候補は根拠にしない
2. **別名と作品名の一致**(外側の名前から作った別名など)。公開 DB 由来の別名は連携の確信度がそのまま根拠の
   確信度になるので、同じ項目に linked した 2 作品どうしも「同じ作品」の証拠になる(弱い連携なら確認待ちになるだけ)。
   両方の作品が同じ取得元・同じ公開 DB 項目(`source`・`source_id`)に linked している場合、その別名一致を
   確信度 0.9 として扱い、手動の決定が絡まなければ自動統合する(`_alias_evidence` が `work_links` の一致で引き上げる)。
   元の別名の確信度は `alias_confidence` として根拠に残し、選んだ項目も `shared_item` に残す。
   また、外側アーカイブ名由来の別名(`source=container`)が別の作品の作品名と完全一致する場合も、
   確信度 0.9 として扱い、手動の決定が絡まなければ自動統合する(#214。外側アーカイブ名の別名は
   そのソースに 1 作品しか入っていないときだけ付けるため誤統合のリスクが低く、元の確信度 0.5 は
   `alias_confidence` に残す)

確信度が 0.9 以上で、**どちらの作品にも手動の決定(手で直した作品名・著者・手動の巻の割り当て・手動で選んだ公開 DB の連携)が絡まない**ものだけ自動で統合する(`AUTO_MERGE_MIN`)。
0.5 以上 0.9 未満、または手動が絡むものは提案(`open`)にして、利用者が「同じ作品として統合」/「別の作品」を選ぶ。0.5 未満は出さない。

- 作品の著者を寄せるとき、手動の著者はファイル名由来の著者より優先する(吸収される側が手動ならその著者を移す)。別名の追加で自動統合が起きて操作した作品が吸収されたときは、API は吸収先の詳細を返し、画面もそちらのページへ移る
- 統合は `merged_into` を張るだけで、巻・読書位置・別名は消えない(統合された側の名前は別名として残る)。作品のブックマークは吸収先へ移る([[bookmarks]])。
  統合後に別の作品の `merged_into` を辿る必要が無いよう、統合先は常に根へ付け替える(平坦化)
- 提案は履歴を兼ねる(`open` / `auto` / `approved` / `dismissed`)。画面の「統合の根拠」はこの行を出している
- **既にある行は再計算で自動適用しない。ただし `open` は、後から確信度が 0.9 以上になり手動の決定が絡まなければ自動で統合する**(#162。行は `auto` の記録として残る)。`dismissed` は復活せず、却下は戻せるだけ。根拠が消えた `open` は派生データなので消す
- **利用者が巻を別の作品へ分けると、その組を `dismissed` の提案として記録する**(`_mark_separated`)。そうしないと、
  同じ重複候補の証拠で次の再計算が即座に元へ統合してしまう。画面の「却下・分けたものを表示」から「提案に戻す」で取り消せる
- **見えている巻を持たない作品は、確認待ちの提案にしない**(自動統合の対象には残す)。巻の組み替えで空になった作品は
  一覧にも提案の画面にも出ないので、行だけが増える。自動統合は空の作品を片付けるのに使えるため残す

## 手動の決定を守る

`CLAUDE.md` の「手で編集した項目を外部ソースで上書きしない」を、最初から項目単位で守れるようにしている。

- 作品名・著者を手で直すと `manual = 1`。再計算は触らない。直す前の作品名は別名(`previous_title`・手動)に残す
- 別名は外した(`dismissed_at`)ものを再計算で戻さない
- 巻の付け替えは手動の割り当て(`manual = 1`)で、再計算で動かさない。分解された巻([[volume-split]])の子は親の手動の割り当てを引き継ぐ
- 整理処理([[organize]])が作る CBZ の巻へは、`spinebox/organize/organizer.py:2127 transfer_volume_state()` が元の巻の作品の割り当て
  (手動かどうかも)を写し、元に戻すと逆向きに写す。そうしないと整理しただけで作品から外れる。
  テンプレートどおりの改名・移動は巻 id を変えないので、割り当てはそのまま残る。命名テンプレートの `<作品名>`・`<著者>` は
  この作品の項目(統合されていれば吸収先)から取る

## 欠け巻と重複

`spinebox/works.py:1636 number_summary()` が、巻と話を別々に 1..最大 のうち範囲(`第01-04巻`)に覆われない番号を欠けとして数える。
最大が 500 を超えると数えない(`limited`。名前の誤読で何千件も欠けを出さない)。**巻の番号を持つ巻が 1 つでもある作品では、話の欠けを数えない**(話・章は巻の中身で、別の系列ではない。
章のフォルダを話として読んだ作品で 1..最大 の欠けが何百件も出たため。#248)。`spinebox/works.py:1660 build_slots()` は
同じ (種別, 開始, 終了) の巻を 1 つの枠にまとめ、2 冊以上入った枠を重複として表示する。番号を読めない巻は「番号の読めない巻」に分けて数えない。

## 実データでの結果

`_参考/サンプル本` のスキャンだけだと 3 作品(お気楽領主のローマ字 5 巻・日本語 3 巻、かくかくしかじか)。重複スキャン後に
日本語名の作品へ 1 つに統合され(確信度 0.989: 1 巻 186/188、2 巻 142/146 ページ一致、手動の決定なしなので自動)、作品ページは 1〜6 巻・1 と 2 巻が重複・欠けなし。
かくかくしかじかは別作品で 1〜4 巻・欠けなし(外側の 7z の名前から著者と別名の候補)。

## 検討して採らなかった選択肢

| 案 | 却下した理由 |
| --- | --- |
| 作品を巻の列(`volumes.work_id` など)で持つ | 出所・確信度・手動を項目ごとに持てず、後続の外部ソース・手動編集の保護を載せられない |
| 巻の名前から毎回計算して保存しない | 手動の決定・別名・統合の履歴の置き場が無い |
| 統合を巻の付け替えで実装する(統合された作品を消す) | 取り消せない。`merged_into` なら承認後も根拠と別名が残り、分けられる |
| 重複候補の見た目だけの一致も自動統合する | 巻番号が分からない組は別の巻どうしが似ているだけのことがある(扉絵・同じ作者の別作品)。0.85 で頭打ちにして必ず確認待ちにした |
| 外側のアーカイブ名を常に別名にする | 複数作品の入れ物(「漫画まとめ」など)の名前が別名になり、別作品を混ぜる根拠になる |
| 末尾の番号を名前だけで巻番号にする(`_RULES` に足す) | `Kitchen 2` が作品名のこともある。実データでは末尾の番号はすべて巻番号だったが、蔵書が変われば誤読する。同じ名前の組がそろっているとき、または作品名が日本語のとき(#263)だけ読む |
| 日本語の名前の入れ物は、日本語の系列がほかに無ければローマ字の系列がいくつあってもまとめる(#263) | 詰め合わせ(`詰め合わせ.zip` に `AAA` と `BBB`)を 1 作品にしてしまう。ローマ字の綴りの揺れを 1 つの系列と数える方で、本番の `ヒロインは絶望しました。` の 3 通りの綴りもまとまった |
| ローマ字を日本語の読みに変換して突き合わせる(pykakasi など) | 漢字の読みが一意に決まらず(`固有` と `Koyuu`、`スキル` と `Skill`)、英語混じりのローマ字は変換で結べない。入れ物の中に他の候補が無いことを根拠にする方が誤りが少なく、依存も増えない(#247) |
| 末尾の番号は読まず、番号なしのまま 1 作品にまとめる | 作品ページが「番号の読めない巻」だけになり、欠け巻・重複枠が出ない。組で読めるなら読む方がよい |
| 数の数えた名前(`57 files`)をそのまま作品名にする | ファイル数・ページ数の見出しが作品名になり、同じ公開 DB 項目に linked した 73 の作品どうしが別名で結ばれて 2000 組超の提案になった(しかも末尾の番号の系列として「files」1〜109 巻にもなる)。作品名として読めない名前は外側へ落とす |
| 同じ公開 DB 項目に linked した作品どうしの別名一致を、統合の根拠から外す | 別名は連携から導出した値なので、同じ項目なら同じ作品である証拠。弱い連携なら確信度が低いまま確認待ちになり、利用者が判断できる。2000 組超は誤連携が原因で、根拠を外すとローマ字と日本語の作品のように他に証拠が無い組まで統合できなくなる |
| 巻の名前から読んだ作品名が今の作品の別名と一致するなら、系列として読めても付け替えない | 公開 DB に linked した 1 巻 = 1 作品は系列名を別名に持つので、末尾の番号の系列(#157)で読めても留まり、同じ項目の別名一致が総当たりの確認待ちとして残った(#162。479 作品・3612 件)。作品名が「系列名 + 番号」そのもののときは、手動の決定が無ければ系列名の作品へ移す |

## 覆すとしたら

自動統合の基準(0.9)は実データが 1 組(お気楽領主)しかなく、他の蔵書では見直す余地がある。下げる前に、
`visual_only` の誤統合(別の巻が似ているだけ)を実データで数えること。
