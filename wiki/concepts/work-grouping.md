# 作品の名寄せ(`spinebox/works.py`)

巻を「作品」にまとめ、作品名・著者・別名と、まとめた根拠を持つ(GOAL.md フェーズ 3)。
作品ページは巻を番号順に並べ、同じ番号の巻は重複としてまとめ、欠けている巻を示す。

## 内容

- **作品は派生データ。** 巻の名前から作る。名前は候補なので([[volume-split]] の巻番号と同じ扱い)、
  作品の項目・別名・巻の割り当てはどれも 1 件ごとに `source`・`manual`・`confidence`・`evidence`(JSON)を持つ。
  入口: `spinebox/works.py:443 sync()`(割り当て `_assign_volumes` → 外側の名前の別名 `_container_aliases` → 提案と自動統合 `_propose_and_merge`)
- **保存先。** 作品 `works`(統合されたものは `merged_into` でリダイレクト)、項目 `work_fields`(title・author を行で持つ。
  項目を足すときは行を足すだけで列は足さない)、別名 `work_aliases`、巻の割り当て `work_volumes`(巻あたり 1 行)、
  統合の提案と履歴 `work_merge_proposals`。`spinebox/db.py:40 MIGRATIONS` の版 6。「手動か」「出所」は
  項目・別名・割り当ての全部が持つので、公開 DB の取得([[metadata-linking]])・手動編集の保護・全文検索はこの列に乗せる
- **名前の読み方。** `spinebox/naming.py:211 parse_work_name()` が巻番号・配布元・タグ・拡張子を落とした作品名と著者の候補を返し、
  `spinebox/naming.py:179 normalize_title()` が突き合わせ用に正規化する(大文字小文字・全角半角・かな種の差を畳む)。
  簡体字の巻表示・話表示(`卷` `话`)は正規の字(`巻` `話`)と同じに読む(`spinebox/naming.py _fold_chars`)。
  巻の**自分の名前**(巻 → 入れ子 → 外側の順で最初に作品名と読めたもの)が既存の作品名・別名と一致すればその作品、無ければ新しい作品
- **小数点の巻は番号なしの巻として作品に入れる。** `第04.5巻` は整数の `number_start`/`number_end` で持てないので番号にせず
  (`parse_number()` は小数点の内側の `5巻` を拾わない)、作品名にも残さない(`parse_work_name()` が末尾の `第N.M巻/話` を落とす)。
  欠け巻・重複枠の計算には入れず、番号の読めない巻として扱う
- **数の数えた名前は作品名にしない。** 配布元の接頭辞(`DLRAW.AC_`)を落とすと残る `57 files` `4 cover` のような名前は、
  ファイル数・ページ数の見出しで、作品名ではない(`spinebox/naming.py _COUNT_NAME`)。実データ(#158)では 1〜109 files などの
  74 作品・184 巻がこれでできていた。自分の名前が読めないので、外側の名前(`あつまれ!ふしぎ研究部 第01-20巻.rar`)から
  作品を読む(確信度 0.6)か、どこからも読めなければ「作品にならなかった巻」になる。
  この名前を読ませると、同じ公開 DB 項目に linked した 73 の作品どうしが別名で結ばれて 2000 組超の提案になり、
  末尾の番号の系列(#157)としては「files」1〜109 巻という作品にもなる
- **確信度の目安。** 自分の名前から 0.9、巻の名前に作品名が無く外側の名前から読んだものは 0.6(`CONF_*` 定数)。
  外側のアーカイブ・フォルダの名前は、**その全部の巻が 1 つの作品に入っているときだけ**別名・著者の候補(0.5)にする
  (複数作品の入れ物の名前を別名にすると、別作品を混ぜる根拠になるため)
- **末尾の番号は、同じ名前の組がそろっているときだけ巻番号と読む。** `作品名 01` `作品名(3)` の形は
  名前だけでは巻番号と決められない(`Kitchen 2` が作品名のこともある)ので、`spinebox/naming.py parse_number()`
  は拾わず、`trailing_number()` が候補を返すだけ。`spinebox/works.py _trailing_series()` が、
  同じ名前で末尾の番号だけが違う巻が 2 つ以上ある組に限り、番号を `volumes.number_*` に入れて作品名から番号を落とす。
  組が 1 つに減れば番号は消え、作品名も元へ戻る(名前から導出した値なので残さない)。
  末尾の番号の後ろの括弧の装飾(`[レーベル]` `(レーベル)` `[AVIF]` など)と著者列(` - 著者 & 著者`)は装飾として落としてから読む。
  落とした部分は番号の根拠(`evidence`)に残す。数字の括弧(`(3)`)は従来どおり番号
  この形を読まないと 1 巻 = 1 作品に分裂し、公開 DB のシリーズ別名が全作品に付いて統合の提案が総当たりになる
  (実データ 2026-11-06: 4610 巻のうち 782 巻・73 組が該当。確認待ちの提案 6123 件のうち 3500 件超がこれだけで消えた)
- **系列として読めた巻は、系列名を別名に持つだけの 1 巻作品に留めない。** 巻の割り当ては、読み直した作品名が
  **今の作品の名前のどれか**(別名を含む)と一致すれば動かさないが、公開 DB に linked した 1 巻 = 1 作品は
  系列名を別名として持つため、系列として読めても留まっていた(#162)。作品名が `系列名 + 末尾の番号` そのもの
  (例: `作品名 01`)で、手動の決定(作品名・巻の割り当て・公開 DB の連携)が絡まないなら系列名の作品へ付け替える
  (`spinebox/works.py _leaves_numbered_work()`)。付け替え先も、番号付きの作品(系列名を別名で持つだけ)には寄せず、
  無ければ系列名の作品を作る。留まると 1 巻 = 1 作品のまま、同じ公開 DB 項目の別名一致が総当たりの確認待ちになる
  (実データ 2026-11-06: 1187 作品・確認待ち 3949 件のうち、この形が 479 作品・65 シリーズ、3612 件がこれに絡んでいた)

## 統合の規則

別々の作品が同じ本と言える根拠は 2 つ。

1. **重複候補の証拠**([[duplicate-detection]])。確信度は一致ページ比。巻番号まで同じ(`same_number`)ならその値、
   見た目だけ(`visual_only`)は 0.85 で頭打ち(`VISUAL_ONLY_CAP`)にして自動統合に回さない。却下された重複候補は根拠にしない
2. **別名と作品名の一致**(外側の名前から作った別名など)。公開 DB 由来の別名は連携の確信度がそのまま根拠の
   確信度になるので、同じ項目に linked した 2 作品どうしも「同じ作品」の証拠になる(弱い連携なら確認待ちになるだけ)。
   両方の作品が同じ取得元・同じ公開 DB 項目(`source`・`source_id`)に linked している場合、その別名一致を
   確信度 0.9 として扱い、手動の決定が絡まなければ自動統合する(`_alias_evidence` が `work_links` の一致で引き上げる)。
   元の別名の確信度は `alias_confidence` として根拠に残し、選んだ項目も `shared_item` に残す

確信度が 0.9 以上で、**どちらの作品にも手動の決定(手で直した作品名・著者・手動の巻の割り当て・手動で選んだ公開 DB の連携)が絡まない**ものだけ自動で統合する(`AUTO_MERGE_MIN`)。
0.5 以上 0.9 未満、または手動が絡むものは提案(`open`)にして、利用者が「同じ作品として統合」/「別の作品」を選ぶ。0.5 未満は出さない。

- 作品の著者を寄せるとき、手動の著者はファイル名由来の著者より優先する(吸収される側が手動ならその著者を移す)。別名の追加で自動統合が起きて操作した作品が吸収されたときは、API は吸収先の詳細を返し、画面もそちらのページへ移る
- 統合は `merged_into` を張るだけで、巻・読書位置・別名は消えない(統合された側の名前は別名として残る)。作品のブックマークは吸収先へ移る([[bookmarks]])。
  統合後に別の作品の `merged_into` を辿る必要が無いよう、統合先は常に根へ付け替える(平坦化)
- 提案は履歴を兼ねる(`open` / `auto` / `approved` / `dismissed`)。画面の「統合の根拠」はこの行を出している
- **既にある行は再計算で自動適用しない。ただし `open` は、後から確信度が 0.9 以上になり手動の決定が絡まなければ自動で統合する**(#162。行は `auto` の記録として残る)。`dismissed` は復活せず、却下は戻せるだけ。根拠が消えた `open` は派生データなので消す
- **利用者が巻を別の作品へ分けると、その組を `dismissed` の提案として記録する**(`_mark_separated`)。そうしないと、
  同じ重複候補の証拠で次の再計算が即座に元へ統合してしまう。画面の「却下・分けたものを表示」から「提案に戻す」で取り消せる
- **見えている巻を持たない作品は、確認待ちの提案にしない**(自動統合の対象には残す)。巻の組み替えで空になった作品は
  一覧にも提案の画面にも出ないので、行だけが増える。自動統合は空の作品を片付けるのに使えるため残す

## 手動の決定を守る

`CLAUDE.md` の「手で編集した項目を外部ソースで上書きしない」を、最初から項目単位で守れるようにしている。

- 作品名・著者を手で直すと `manual = 1`。再計算は触らない。直す前の作品名は別名(`previous_title`・手動)に残す
- 別名は外した(`dismissed_at`)ものを再計算で戻さない
- 巻の付け替えは手動の割り当て(`manual = 1`)で、再計算で動かさない。分解された巻([[volume-split]])の子は親の手動の割り当てを引き継ぐ
- 整理処理([[organize]])が作る CBZ の巻へは、`spinebox/organize/organizer.py:2015 transfer_volume_state()` が元の巻の作品の割り当て
  (手動かどうかも)を写し、元に戻すと逆向きに写す。そうしないと整理しただけで作品から外れる。
  テンプレートどおりの改名・移動は巻 id を変えないので、割り当てはそのまま残る。命名テンプレートの `<作品名>`・`<著者>` は
  この作品の項目(統合されていれば吸収先)から取る

## 欠け巻と重複

`spinebox/works.py:1089 number_summary()` が、巻と話を別々に 1..最大 のうち範囲(`第01-04巻`)に覆われない番号を欠けとして数える。
最大が 500 を超えると数えない(`limited`。名前の誤読で何千件も欠けを出さない)。`spinebox/works.py:1109 build_slots()` は
同じ (種別, 開始, 終了) の巻を 1 つの枠にまとめ、2 冊以上入った枠を重複として表示する。番号を読めない巻は「番号の読めない巻」に分けて数えない。

## 実データでの結果

`_参考/サンプル本` のスキャンだけだと 3 作品(お気楽領主のローマ字 5 巻・日本語 3 巻、かくかくしかじか)。重複スキャン後に
日本語名の作品へ 1 つに統合され(確信度 0.989: 1 巻 186/188、2 巻 142/146 ページ一致、手動の決定なしなので自動)、作品ページは 1〜6 巻・1 と 2 巻が重複・欠けなし。
かくかくしかじかは別作品で 1〜4 巻・欠けなし(外側の 7z の名前から著者と別名の候補)。

## 検討して採らなかった選択肢

| 案 | 却下した理由 |
| --- | --- |
| 作品を巻の列(`volumes.work_id` など)で持つ | 出所・確信度・手動を項目ごとに持てず、後続の外部ソース・手動編集の保護を載せられない |
| 巻の名前から毎回計算して保存しない | 手動の決定・別名・統合の履歴の置き場が無い |
| 統合を巻の付け替えで実装する(統合された作品を消す) | 取り消せない。`merged_into` なら承認後も根拠と別名が残り、分けられる |
| 重複候補の見た目だけの一致も自動統合する | 巻番号が分からない組は別の巻どうしが似ているだけのことがある(扉絵・同じ作者の別作品)。0.85 で頭打ちにして必ず確認待ちにした |
| 外側のアーカイブ名を常に別名にする | 複数作品の入れ物(「漫画まとめ」など)の名前が別名になり、別作品を混ぜる根拠になる |
| 末尾の番号を名前だけで巻番号にする(`_RULES` に足す) | `Kitchen 2` が作品名のこともある。実データでは末尾の番号はすべて巻番号だったが、蔵書が変われば誤読する。同じ名前の組がそろっているときだけ読む |
| 末尾の番号は読まず、番号なしのまま 1 作品にまとめる | 作品ページが「番号の読めない巻」だけになり、欠け巻・重複枠が出ない。組で読めるなら読む方がよい |
| 数の数えた名前(`57 files`)をそのまま作品名にする | ファイル数・ページ数の見出しが作品名になり、同じ公開 DB 項目に linked した 73 の作品どうしが別名で結ばれて 2000 組超の提案になった(しかも末尾の番号の系列として「files」1〜109 巻にもなる)。作品名として読めない名前は外側へ落とす |
| 同じ公開 DB 項目に linked した作品どうしの別名一致を、統合の根拠から外す | 別名は連携から導出した値なので、同じ項目なら同じ作品である証拠。弱い連携なら確信度が低いまま確認待ちになり、利用者が判断できる。2000 組超は誤連携が原因で、根拠を外すとローマ字と日本語の作品のように他に証拠が無い組まで統合できなくなる |
| 巻の名前から読んだ作品名が今の作品の別名と一致するなら、系列として読めても付け替えない | 公開 DB に linked した 1 巻 = 1 作品は系列名を別名に持つので、末尾の番号の系列(#157)で読めても留まり、同じ項目の別名一致が総当たりの確認待ちとして残った(#162。479 作品・3612 件)。作品名が「系列名 + 番号」そのもののときは、手動の決定が無ければ系列名の作品へ移す |

## 覆すとしたら

自動統合の基準(0.9)は実データが 1 組(お気楽領主)しかなく、他の蔵書では見直す余地がある。下げる前に、
`visual_only` の誤統合(別の巻が似ているだけ)を実データで数えること。
