# 巻への分解と巻範囲の食い違い

複数巻をまとめた内側アーカイブ(実データ: `第01-04巻.7z` の中の `v01-03.rar`)を、開いたときに中の巻ごとの「子の巻」に分け、
名前の巻範囲(`v01-03` → 1〜3)と中に見つかった巻番号を比べて、欠け・余りを一覧に出す。#30 で作った。

## 内容

### 巻番号の候補(名前から読む)

- 入口: `spinebox/naming.py:153 parse_number()`。結果は `NumberCandidate(kind, start, end, evidence)`。kind は `volume` / `episode`
- **保存場所は `volumes` の `number_kind` / `number_start` / `number_end` / `number_evidence`**(`spinebox/db.py:40 MIGRATIONS` の 2 番)。
  スキャンが切り出す巻は `spinebox/scanner.py:723 _replace_volumes()` が、子の巻は `spinebox/analysis.py:63 register_units()` が書く。
  後続の重複検出はここを読む(作品の同一性は持っていないので、それは別に要る)
- 名前は**候補**であって確定ではない(CLAUDE.md の不変条件)。ここで「確定」は作らない。API でも `volume_number` という候補として返す
- 拾わないもの: 印の無い単独の数字(`DLRAW.TO_001.jpg` の 001)、`全3巻`、語の途中の `v`(`Dev01`)、年・日付らしい範囲。
  印の無い範囲 `01-03` は最も弱い規則として最後に試す
- **巻のフォルダの中の章は巻番号にしない(#248)。** アーカイブ内の外側のフォルダ・内側アーカイブの名前が 1 冊の巻
  (`…v06s`)を表すとき、その中のフォルダの印の無い範囲(`DLRAW.AC_110-113`)と話・章(`… Raw Chapter 171`)は
  章の番号なので読まず、番号なしにする(`spinebox/naming.py parse_number_in()`。呼ぶのはスキャンの `archive_volume_specs` と
  分解の `Unit.ancestors`)。外側が範囲(`第01-20巻`)なら中は巻のことがあるので従来どおり読み、
  巻の印の付いた名前(`v07`)も外側に巻があって読む。読ませると実データ(あつまれ！ふしぎ研究部)で欠け巻が 35 から膨らんだ
- `作品名 01` `作品名(3)` の形も `parse_number()` では拾わない(`Kitchen 2` が作品名のこともある)。
  `spinebox/naming.py trailing_number()` が候補を返し、**同じ名前で末尾の番号だけが違う巻が 2 つ以上**のときだけ
  [[work-grouping]] が巻番号として `volumes.number_*` に入れる(スキャンでは書かない)
- 読み方を変えたら `spinebox/scanner.py:58 SCAN_VERSION` を上げる(既存 DB の巻の候補を読み直させるため)

### 分解(巻の単位と子の巻)

- **巻の単位** = 画像を直接含むフォルダ(アーカイブの直下に画像があれば、そのアーカイブ自体)。入れ子の全段(`max_depth` まで)を見る。
  集めるのは `spinebox/library.py:495 _units()`。各ページがどの単位かは、内側アーカイブを開く `_expand()` が入れ子の名前の並びとして持つ。
  単位の名前(フォルダ名・アーカイブ名)はスキャンの切り出しと同じく `fix_mojibake()` で文字化けを直す(#257。前は直さず、化けた名前が子の巻・作品名になっていた)
- **単位が 2 つ以上のときだけ分解する。** 1 つなら親がそのまま 1 巻(子は作らない。前に作った子は missing にする)
- 子の巻の場所は (親と同じ `source_id`・`container_path`) + `inner_path`(親の内側アーカイブから単位のあるアーカイブまでの名前の JSON 配列)+
  `entry_prefix`(そのアーカイブ内のフォルダ)。開くのは `spinebox/library.py:361 _open_unit()`
- **親は「まとめ」として残す。** 開けば今までどおり全ページを読める。一覧(`LISTED_VOLUMES_WHERE`)は見えている子を持つ親を出さず、子を親の位置に並べる
- 解析する契機: (1) 内側アーカイブの巻を開いたとき(`GET /api/volumes/{id}`。取り出しは済んでいるので追加の展開は無い)、
  (2) 明示操作 `POST /api/volumes/{id}/analyze`(一覧の「中の巻を調べる」)、(3) 設定 `background_analysis = true` のときの裏の少しずつ解析(ほかのジョブが動いていないときだけ。[[data-jobs]])、(4) データ管理の「中の巻を調べる」(未解析を全部)
  (`spinebox/library.py:477 analyze_next()`、1 回に 1 巻、既定は無効)。**スキャンでは解析しない**
- 解析の版 `analyzed_version` = 解析の仕方(`ANALYSIS_VERSION`)・`max_depth`・元ファイルのサイズと mtime。どれかが変われば開いたときに解析し直す。
  スキャンがソースを読み直したときも NULL(未解析)に戻す
- 子は (inner_path, entry_prefix) で突き合わせるので、解析し直しても同じ単位は同じ巻 id(読書位置が続く)。消えた単位は missing にするだけ
- オフラインのルートでは解析しない(409)。裏の解析は記録せずに飛ばし、再接続後にまた候補にする。読めなかった巻は `analysis_error` に理由を残し、
  `analyzed_version = 'error'` にして裏の解析が同じ巻を繰り返さないようにする(明示操作ならやり直せる)

### 分解前に親で挟んだしおり

読書位置と同じく、親の行を残したまま、そのページを持つ子の巻のそのページへ写す(`spinebox/analysis.py:130 _carry_page_marks()`。#136、[[manga-reader]])。
子に既にあるしおりは触らない。題は持たないので、ページ番号が変わっても「ページN」がずれない

### 分解前に親で付けた読書位置

`spinebox/analysis.py:102 _carry_progress()`。親の記録は消さない。位置を持たない子にだけ写す。

- 親が既読 → 全部の子を既読(最終ページ)
- 親の位置のページを含む子 → そのページから(既読でない)
- 親のページ順でそれより前のページしか持たない子 → 既読
- それより後の子 → 未読のまま

### 食い違い

`spinebox/analysis.py:214 compute_findings()`(`source_ids` を渡すとそのソースの巻だけ読む。1 巻を開くときはこちら。#294)。DB に保存せず、一覧・詳細のたびに巻番号の列から導出する(巻番号が正なので、食い違いを別に持つと古くなる)。

- `volume`: 分解した親の名前の範囲 ⇔ 子の巻番号。親と各子に付ける
- `source`: 外側アーカイブ(スキャンのソース)の名前の範囲 ⇔ その中の巻(分解済みなら子、未解析の内側アーカイブはその名前の範囲)。
  直下に画像があるだけの外側アーカイブは比べない(アーカイブ自体が 1 巻で、名前どうしを比べることになる)。同じ欠け・余りなら `volume` の方だけ付ける
- 出すのは **欠け(missing)と余り(extra)だけ**。比べるのは巻どうし。話数の名前・番号の読めない単位は `unnumbered` に数えて文面で触れる

## なぜこうなっているか

- **同じ巻番号が複数ある(重複)を食い違いにしない。** 実データのお気楽領主の zip(名前 v01-06)は 1,1,2,2,3,4,5,6 巻のフォルダを持つ(別スキャンの重複)。
  重複を食い違いとして出すと、まとめアーカイブのほとんどに印が付いて本当の欠けが埋もれる。重複は [[duplicate-detection]](#38)が候補として出す。
  `duplicates` は finding の中に情報として入れているが、それだけでは finding を作らない
- **解析を開いたときに行う。** 内側アーカイブを開けば全段を取り出し済みで、巻の単位は目次から分かる。追加の展開無しで分解できる。
  スキャンで行うと「スキャンでは内側のアーカイブを 1 つも取り出さない」(フェーズ 1 の完了条件)に反する
- **単位 1 つでは分解しない。** 入れ子でも画像が最深部の 1 か所にしか無いなら、親と同じ巻を 2 つ並べるだけになる
- 子は親と同じキャッシュキーで取り出す([[extraction-cache]])。親を読んだ直後に子を開いても取り出し直さない

## 検討して採らなかった選択肢

| 案 | 却下した理由 |
| --- | --- |
| 食い違いを表に保存する | 巻番号と子の巻から毎回導出できる。保存すると解析し直し・パーサの変更のたびに同期が要る |
| 分解したら親を missing にする | 親の読書位置・親の id を指すブックマークが行き場を失う。親は残し、一覧で隠すだけにした |
| 親の読書位置を子へ移して親の記録を消す | 読書位置は消さない(不変条件と同じ考え方)。写すだけにした |
| ページ番号の連続区間で親の位置を子へ割り当てる | 親のページ順は段ごとに表紙優先の自然順で、子の境目と一致しない。ページの同一性(単位・エントリ名)で引く |
| 名前の範囲が 1 巻だけ(`v02`)なら比べない | `v02` の中に 1 巻と 2 巻があるのも食い違い。範囲か単独かで分けない |

## 覆すとしたら

- 中身から巻番号を確定できるようになったら(メタデータ・見た目の比較。フェーズ 3)、比べる相手を候補から確定値へ替える
- フェーズ 2 の CBZ 化([[organize]])で 1 巻 = 1 CBZ になれば、内側アーカイブの巻は減り、分解の出番は小さくなる。
  整理の単位は子を持たない巻(分解済みなら子の巻ごと)で、未解析の内側アーカイブは先に調べるまで整理しない
- 子の名前の生バイト列(`name_raw`)は持っていない(NULL)。名前の文字コードが問題になったら単位にエントリの生バイト列を持たせる
