# フォロー(続刊・欠けの通知)

フォローした作品について、**蔵書に無い巻番号**(手元の最大の巻より後 = 続刊、間 = 欠け)と発売日を公開 DB で調べて知らせる(#87)。
入口は `spinebox/follows.py:115 check_work()`(調べる)と `spinebox/follows.py:284 list_releases()`(サイドバーの「フォロー」)、
`spinebox/follows.py:266 list_follows()`(フォロー管理)。画面は `frontend/src/follows/Follows.tsx:94 FollowReleases()`(`#/follows`)・
`frontend/src/follows/Follows.tsx:155 FollowManage()`(管理の「フォロー管理」タブ `#/admin/follows`。旧 `#/follows/manage` も同じタブを開く)・作品ページの `frontend/src/follows/Follows.tsx:277 WorkFollowPanel()`。
タイトル一覧(`frontend/src/works/WorkTitles.tsx:18 WorkTitles()`)も、その作品の欠け・最新巻を点線の行で出す(#115)。

## 読み替え

Peach のフォローは追いかけている対象の新着を見る機能。SpineBox で同じ画面構成(#85)にするとき、新着を「持っていない新しい巻」に読み替えた。
**知らせるだけで、入手(ダウンロード・購入サービスへのリンクや連携)はしない**(GOAL.md「作らないもの」)。見せるリンクは国立国会図書館サーチの書誌のページだけ。

## 取得の方針

| 規則 | 理由 |
| --- | --- |
| 数えるのは国立国会図書館サーチの**連携した組**([[metadata-linking]] の `_ndl_groups()`)の巻ごとの書誌だけ | 巻ごとの発売日を持つのは NDL だけ(メディア芸術データベース・Bangumi は作品単位で、全巻数はあっても各巻の発売日が無い)。組は種別・作品名・シリーズ名・著者が同じ書誌なので、**漫画と小説が同名で並ぶ作品(お気楽領主)でも、連携した種別の巻だけが数えられる** |
| 調べるときは `linking.fetch_work(..., sources=("ndl",))` で連携を取り直し、その中身で数える。保存済みの応答の有効期限だけ短くする(`[follow] response_ttl_days`、既定 1 日) | 連携の判定(自動/確認待ち・種別の保留・手動の固定)を別に書かず #50 の規則に乗せる。補完の有効期限(30 日)のままだと新刊が 1 か月拾えない。レート制限の関門は補完と共有する(`spinebox/app.py:287 follow_service()` は元の設定の共有 fetcher を明示的に渡す。設定を変えたものを渡すと共有の fetcher が作り直されて関門がリセットされる) |
| 連携が確認待ち・該当なしなら数えない(`unlinked`)。作品ページで候補を選ぶと次の確認で数える | 漫画か小説か決まらないうちに数えると、小説の 4〜6 巻を漫画の続刊として出す(実データのお気楽領主で起きる) |
| 作品の種別と連携の組の種別が違えば数えない(`kind_mismatch`) | 手動で種別を直した後も、手動の連携は再取得で変わらないため |
| 手元の巻に巻番号が読める巻が 1 つも無ければ数えない(`no_numbers`)。取得元にも問い合わせない | 話数だけの作品・番号の無い単巻で、全巻を「欠け」として出さない |
| 取得に失敗しても例外にせず、前回までの連携の中身で数えて `follows.failure` に残す(連携も前回の結果も無ければ `failed`) | CLAUDE.md の「取得失敗でスキャンと閲覧を止めない」。フォローの一覧・作品ページ・閲覧は DB だけで返す |
| NDL は短時間に続けて要求すると 429 を返す(実通信で、補完で 4 回ほど続けた直後に出た。`Retry-After` 60 秒。約 1 分で戻った)。**連携の後に作品名が日本語に替わると、続刊の確認の検索語が連携のときと違い(ローマ字 → 日本語)、保存済みの応答に当たらず 1 回取りに行く**。以後は有効期限内なら取りに行かない | 失敗は `follows.failure` に残して前回までの連携で数える扱いが効く。続刊の確認を一斉にかけるときは作品ごとに最小間隔を空ける(関門は共有) |
| 一覧に見えている巻(オフラインのルートの巻を含む)を「持っている」とする。範囲の巻(`v01-03`)は範囲すべて | 外付けドライブ未接続で全巻が欠けとして出ないように(CLAUDE.md のオフラインの不変条件) |
| 発売日の並びは `2015` / `2015-03` / `2015-03-15` を `YYYY-MM-DD` に足して(足りない月・日は `00`)比べる(`spinebox/follows.py:303 _desc()`) | 足さないと文字列の鍵では `2015` が `2015-03` より先に並び、同じ年の中で月の分からない巻が新しい扱いで先頭に出た(#93) |

## 確認済みと、蔵書に入った巻

- `follow_releases` は作品 × 巻番号で 1 行(マイグレーション 13)。**続刊か欠けかは保存せず、表示のときの手元の巻番号で決める**。蔵書に入った巻は調べ直さなくても出なくなる
- 「確認済み」(`seen_at`)は再確認でも消さない。新しい巻だけが未確認として出る。書誌から消えた巻は、未確認のものだけ外す
- フォローを外しても `follow_releases` は残す。フォローし直したときに確認済みの巻が再び出ないように
- 統合で吸収された作品のフォローと見つけた巻は、一覧・詳細を返すときに吸収先へ移す(`spinebox/follows.py:65 resolve_merged()`。確認済みはどちらかにあれば残す)。統合の経路が多いので、各経路に足さず読む側でまとめた

## 確認のタイミング

- 明示操作: フォロー管理の「続刊を調べる」(全作品・1 作品)。`POST /api/follows/check` はデータ管理のジョブ `follow_check`([[data-jobs]])として 1 本ずつ動く(同じ取得元を叩く補完・重複・表紙と並ばない)。既定は待ち行列に入れて 202、`wait=true` でほかのジョブが動いていれば 409。中止できる(調べた作品の結果は記録済み)
- 定期実行: `[follow] background = true` のときだけ(既定は無効)。`background_interval_seconds` ごとに裏の定期処理(ジョブ `background_follow`。何も動いていないときだけ)が見回り、`interval_hours` 以上調べていない作品を 1 回に 1 作品。続けて動いた分は履歴の 1 行にまとまる
- **#83 のジョブに載せた(`spinebox/datajobs.py _follow_check()` / `background_follow()`)。** 手順は `follows.check_many()` に `progress(done, total, 現在の作品)` を渡し、中止は 1 作品ごとの区切り。画面は #85 で組み込み済み:
  `followsHref` はサイドバーの「フォロー」、`followManageHref`(`#/admin/follows`)は管理の「フォロー管理」タブ(`FollowManage` の `embedded`)。作品一覧のヘッダーに置いていた「フォロー」のリンクは外した

## 却下した案

| 案 | 却下した理由 |
| --- | --- |
| メディア芸術データベース・Bangumi の全巻数(`total_volumes`)と手元の最大巻の差で続刊を出す | 発売日が無く「新しい発売日順」にできない。Bangumi は漫画と原作小説の巻が混ざって全巻数が過多になることがある([[metadata-sources]]) |
| フォロー専用に NDL を検索し、連携とは別に結果を持つ | 種別の判定・手動の連携の固定を二重に書くことになり、作品ページの連携と食い違う |
| 見つけた巻を「続刊」「欠け」として保存する | 欠けの巻をスキャンで足すと、手元の最大巻が変わって続刊の巻が欠けになる。表示のときに決めれば記録を書き換えずに済む |
| フォローを外したら見つけた巻も消す | 確認済みの印が消え、フォローし直すと同じ巻を何度も出す(#87 の受け入れ基準に反する) |
